# 数字电源基础工程

本仓库是一个面向数字电源开发和验证的基础工程，用于组织可复用代码、不同硬件平台以及仿真分析环境。工程重点关注控制算法、平台适配和公共基础能力之间的解耦，便于在不同项目中移植和验证。

## 工程内容

仓库围绕数字电源从算法设计到平台运行的基本流程进行组织，主要包括以下几类内容：

- 可复用的控制、基础算法、任务调度、通信和调试代码；
- 面向不同芯片与硬件环境的平台工程和接口适配；
- 用于控制器设计、动态分析和功能验证的 MATLAB 与 PLECS 仿真；
- 配套的设计、应用、测试、教材和其他文档。

这些内容共同构成一套相对完整的开发基础，既可以单独研究某个控制或算法问题，也可以把公共代码接入具体平台进行联合验证。

## 设计思路

公共代码尽量保持硬件无关，通过统一接口访问采样、PWM、通信和其他硬件资源。芯片、外设和编译环境的差异由平台层处理，使控制逻辑能够在仿真环境与实际工程之间复用。

控制功能通常先完成数学建模和参数设计，再进行原理性时域分析与开关级仿真，最后接入硬件工程验证。工程同时保留必要的观测、保护和调试能力，方便定位算法、时序和平台适配问题。

## 一些平平无奇的工程习惯

工程里没有使用太多特别新奇的做法，主要是把一些容易被省略的环节尽量补完整：

- 控制器先经过频域设计和时域验证，再进入 PLECS 与嵌入式工程；
- 仿真平台可以直接复用部分实际控制代码，减少模型逻辑与固件逻辑之间的偏差；
- 同时保留浮点和整数控制实现，对采样代码域、PWM 代码域、限幅和量化误差进行明确处理；
- 公共代码通过注册和统一调度机制接入不同运行环境，平台切换时通常不需要改动算法主体；
- 除了让功能运行起来，也保留性能统计、波形观测、运行跟踪和在线分析能力；
- 编译、仿真、下载和验证过程尽量脚本化，方便重复执行同一套检查。

单独看这些内容都比较常见，放在一起只是为了让一个控制算法从公式走到仿真、再走到硬件时少绕一点路。

## 使用方式

使用本工程时，可以根据目标选择公共模块并完成平台接口绑定，也可以先运行已有仿真了解控制特性和参数影响。涉及工程结构、模块设计、接入步骤和验证结果的详细内容统一在 [文档索引](docs/DOCUMENT_INDEX.md) 中维护。

## 仓库目录

| 目录 | 内容 |
|------|------|
| `code/` | 平台无关的应用、通信、控制、调试、接口、算法库和 Section 框架 |
| `platform/` | MCU、Zynq、MATLAB 与 PLECS 平台工程、硬件适配及平台专用工具 |
| `tests/host/` | 使用 MinGW 运行的平台无关模块测试 |
| `verilog/` | 可复用 FPGA IP；每个 IP 按 `rtl/`、`sim/` 和 `doc/` 组织 |
| `docs/` | 按设计、应用、测试、教材和其他五类组织的工程文档 |

本工程主要用于技术积累、方案验证和模块复用，不代表某个具体产品的完整固件。
