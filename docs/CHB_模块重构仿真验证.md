# CHB 模块重构仿真验证

日期：2026-10-02。结果：通过。验证对象为当前模块架构、HAL 静态采样、my_math LPF/限幅、滑窗 RMS、app PLL、电网启动资格判断及 Kp/Ki 计算宏的实际接入，以及工作区 `platform/plecs/chb/chb.plecs`。两轮实际开关模型仿真均使用本次重新编译的控制 DLL，文件标识见文末。

主机控制测试使用理想电网夹具提供 RMS、角频率和相位。app 测量和启动资格的通过结论来自实际 PLECS 模型与 FRAME 通信测试。

## 测试条件与执行方式

- PLECS Standalone 5.0，MinGW GCC 14.2.0；DLL 使用 Release 构建及工程严格警告选项。
- 实际开关模型：五桥串联，电网 10 kV RMS / 50 Hz，输入电感 12 mH，每桥母线电容 600 µF、目标 3200 V、负载功率上限 20 kW。
- 控制与 PWM 10 kHz，原采样平均、PWM 更新延迟、死区及求解容差保持不变。
- PLECS 闭环仿真 4.7 s；先保持 Shell 请求为零，约 0.5 s 显式启动，1.5 / 2.5 / 3.5 s 切换各桥电阻，约 4.5 s 带载停机。
- PLECS 电网资格仿真 2.9 s；改变源电压和频率，检查连续资格、请求清除、运行撤销及恢复后禁止自动重启。
- 另运行 CHB 主机闭环测试台 24 s，轮换各桥限功率并恢复，检查启动、取消继电器等待、软起超时、非法初始采样、过流停波和故障恢复。

在仓库根目录执行：

```powershell
cmd /c platform\plecs\chb\compile.bat
C:/mingw64/bin/mingw32-make.exe -C platform/testbench/chb -B run
python platform/plecs/chb/tests/run_simulation.py
python platform/plecs/chb/tests/run_simulation.py --qualification
```

运行 PLECS 测试前启用本机 RPC（1080 端口）。脚本读取实际模型中的 DLL 路径及继电器类型，有界等待控制 FRAME（5004 端口），电网源通过 5005 端口调整。命令按现有仿真时钟安排，每轮求解限时 600 s，检查 CRC、回执、状态、物理采样及完整仿真完成情况。日志与 JSON 结果保存在 `platform/plecs/chb/build/simulation-test/`，闭环为 `result.json` / `plecs-log.txt`，资格场景为 `qualification-result.json` / `qualification-plecs-log.txt`。

电网原始采样 RMS 为 9999.99 V，RUN 电流采样峰值为 20.275 A，记录了 6804 组 PWM 同拍采样。显式启动前 app 实测 RMS 为 10000.070 V、PLL 频率为 50.00076 Hz。约 1.101 s 进入 RUN，4.504 s 回到 IDLE，各桥 PWM 命令归零，物理输入电流为 0.000000 A，仿真完成到 4.7 s。

测试台全部断言通过：各阶段母线误差小于 12 V，各桥持续负载功率不超过 20.05 kW，全程物理积分电流峰值 28.71 A；过流在同拍禁止 PWM。

## Kp/Ki 宏的实际应用

`chb_cfg.c` 的默认能量环和电流环配置直接调用 `cfg.h` 中的 Kp/Ki 计算宏；默认电感和电流增益共用 `CHB_L_GRID_DEFAULT`。能量环采用自然角频率 20 rad/s、阻尼比 1；电流环采用 763.7626158 rad/s、阻尼比 3.273268354，对应已有的过阻尼整定点。电容已进入能量误差，不在增益中再次计入。自定义配置仍可显式提供增益，改变自定义电感后须用宏重新生成对应电流增益。

app 在 INIT 通过现有 `pll_update_pi` 接口应用 PLL 宏，输入是额定电压峰值、原阻尼比和自然角频率。默认配置的增益在编译期生成，PLL 的计算及应用只发生在 INIT，周期控制不重复计算。

| 环路 | 实际 Kp | 实际 Ki |
|---|---|---|
| 母线能量环 | 40 | 400 |
| 电流环 | 60.0000076 | 7000.00049 |
| PLL | 0.0125663709 | 1.11661839 |

增益核对通过：能量环保持原值，电流环与原 60/7000 仅有浮点舍入差异；PLL 应用宏前后的系数及初始化状态逐字节一致。随后重跑主机闭环及两轮实际 PLECS 仿真，均通过。功率限制环的原 1/20 整定不适用上述能量环模型，此次保持其独立配置。

## 电网测量与启动资格

电网任务独立于 Shell 请求持续判断：实测基波 RMS 在额定 90%～110%（9～11 kV）、PLL 频率在 49～51 Hz 内连续满足 200 ms，且 Shell 显式请求启动，才向 FSM 发布有效请求。条件失效时清除 Shell 请求，恢复后需再次显式启动。

| 实际模型刺激 | 观测结果 |
|---|---|
| 0.01 s 提前请求 | 0.012 s 测量尚未建立，请求清除；进入 IDLE 后 PWM 保持零 |
| 0.400 s 源电压降至 8 kV | 0.650 s 实测约 7999.99 V；欠压期间的启动请求清除 |
| 0.75 s 恢复 10 kV 后再次提前请求 | 0.805 s 测得 9926.88 V、49.2463 Hz，连续合格计数仅 4 ms，请求仍被清除 |
| 1.253 s 合格后显式请求 | 经过预充及主继电器等待，1.851 s 进入 RUN |
| 2.0 s 将运行电网升至 52 Hz | 2.010 s 测得 51.5863 Hz，撤销请求；2.011 s 返回 IDLE；2.303 s PLL 已跟随到约 51.9991 Hz |
| 2.353 s 恢复 50 Hz | 2.800 s 测量恢复正常，仍保持请求零、IDLE、各桥 PWM 零和物理电流零 |

这轮动态刺激证明 app 的 RMS 和 PLL 输出由实际波形计算，跟随源变化。频率阈值在初始化时转换为 rad/s，与 HAL 的 `2*pi*f` 输入一致；脚本读取 Hz 诊断量检查测量。

## 测试中修复的问题

此前初轮脚本在约 0.35 s 请求启动，但模型的连续合格计数仅 185 ms，请求被正确清除，未进入预充。将正常启动用例推迟到 0.5 s，并增加提前请求被清除的独立场景后重跑通过。增加仿真时钟诊断和请求撤销日志，保留具体时间、计数、RMS、频率与保护状态；没有缩短资格时间。此次 PI 宏接入保留原整定点，增益核对见上节。

此次资格回归还暴露了脚本结束时序问题：最后一个功能断言已完成，但主循环继续读取仿真时钟，遇到 DLL 关闭 FRAME 端口，报 `FRAME disconnected before its ACK`。现在用例完成后停止通信轮询，并在剩余墙钟预算内等待完整 RPC 求解结果；没有忽略通信错误或提前把用例判为通过。资格场景重新跑到 2.9 s，完整返回并通过。

此前模型适配时，首次带载停机在 4.104 s 失败：理想 `Switch` 立即断开交流电感支路，使输入电感电流被强制从 12.7331 A 跳到零。根据 PLECS 5.0 本机文档 `Using PLECS → Error Messages → State discontinuity after switching` 和 `Components → Breaker`，将主、软起继电器 S2/S1 换成收到断开请求后在电流过零时断开的 `Breaker`。本次沿用该实际模型并再次通过带载停机；没有屏蔽不连续错误或放宽求解容差。

公共 PLECS 适配器新增参数读取时缺少旧模型的默认参数数量，导致旧拓扑编译失败。补上默认零参数配置后，对 ac、boost、buck、chb、cllc、frame_bridge、frame_route_bridge、inv、inv_dq、inv_i32、llc、npc、pfc、pfc_i32 共 14 个入口执行公共适配器编译检查，全部通过。

本次验证覆盖正弦电网下的启动、带载控制、功率限制、恢复与停机，以及欠压和超频时的启动门控及请求撤销。未覆盖全部阈值边界、带载欠压、谐波、THD 或实机性能；52 Hz 的频率刺激用于验证退出逻辑，不代表全工况变频性能通过。
