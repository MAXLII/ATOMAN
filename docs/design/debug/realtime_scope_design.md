# 中断级实时示波器设计方案

日期：2026-10-22。

状态：base 已实现通用采样核心、公共 COMM 注册服务和独立平台适配。ESP32-C5 作为验证平台，已完成实际 ELF 变量、公共控制、独立 Wi-Fi 数据与 FRAME 波形的真机闭环；3 通道 10 kHz、32 通道 5 kHz 通过。当前 ESP32 适配器限 10 kHz，30 kHz 测试触发定时超时，未通过。

## 1. 目标与设计基线

在控制中断的固定位置采集变量，通过专用高速通信链路持续上传，由 FRAME 按变量实际类型解码并实时显示。

已明确的需求：

- FRAME 根据编译产物解析变量名称、地址和类型，支持选择结构体内的具体成员。
- 上下位机固定配置 32 个通道槽位，合法通道号为 1～32，0 及大于等于 33 的编号非法。
- 上位机下发通道号、数据地址、数据类型；下位机以通道号减 1 定位节点数组元素，并按通道号升序连接有效节点。
- 节点仅保存数据地址、数据类型和 p_next，不重复保存通道号。
- 配置、参数同步、启停及状态查询走 FRAME 顶部公共通信链路；独立 Wi-Fi TCP 9001 仅上传 EA 采样数据。
- 设备维护配置链表和活动链表，两者各有独立的 32 槽位节点数组；运行中可修改配置链表，活动链表供采样读取。
- 启用配置时只交换两套配置的角色指针，不从配置链表复制节点或内容到活动链表；两条链表可以互相切换。
- 数据帧顺序为 `EA + index + 数据1 + … + 数据N + 数据长度 + 累加校验和`，index 和校验和各 1 字节。
- 采样频率由下位机中断固定，上位机查询频率及通信预算并显示带宽占用，避免通信溢出。
- 频率以 Hz 设置，时间轴避免累加取整后的微秒周期。
- FRAME 默认保留最近 10 秒数据，容量可配置，实时数据不自动保存到磁盘。
- 提供波形缩放、移动、游标、测量及基本触发操作。

实现基线：带 DWARF 调试信息的 ELF 为自动解析入口，MAP 可选；中断内只采样与写缓冲，后台发送；上位机接收、缓存和绘图分别运行。每个数据帧上传全部有效通道的一次采样，不携带通道号、地址、类型、会话标识或首采样序号。

本版按方案默认值落地：数据长度为 2 字节小端，仅统计数据区；校验为实际帧头 EA 至长度字段末尾逐字节累加的低 8 位，不累计不存在的 E8 字节。

## 2. 总体架构与职责

```text
FRAME 控制路径
ELF/DWARF + 可选 MAP → 变量树 → 单套通道列表 → 公共 E8/E9 → 下位机配置、切换、启停
                                             ↓
下位机采集路径
控制中断固定位置 → 遍历活动链表 → 有界 RAM 缓冲 → 后台发送 / DMA
                                                               ↓
FRAME 数据路径
高速链路 → 接收 → EA 分帧与校验 → 按类型解码 → 环形缓存 → 波形显示
```

| 模块 | 职责 |
| --- | --- |
| FRAME 符号索引 | 解析变量、类型、成员偏移、数组布局及固件标识 |
| FRAME 实时采集服务 | 维护一套 32 槽位通道列表，管理设备同步、采集状态、带宽预算及错误统计 |
| FRAME EA 解码器 | 处理任意接收分块、完整性校验和失步恢复 |
| FRAME 数据缓存 | 保存有界采样历史、主机维护的逻辑采样序号及可识别的数据缺口 |
| FRAME 波形界面 | 通道选择、缩放、平移、测量、触发和状态展示 |
| 下位机采样核心 | 管理两套独立 32 槽位节点数组、有效状态、活动链表和采样缓冲 |
| 下位机控制服务 | 能力查询、配置链表编辑、配置校验、角色切换、启动、停止及状态查询 |
| 下位机链路适配 | 对接具体通信外设、DMA、发送完成及错误事件 |

FRAME 可在现有符号索引、流式解码接口和波形组件上增加实时采集能力。建议由 C++ 后端持有采集状态、协议解析和缓存，C# WPF 负责交互与批量绘图。

base 中现有 Scope 的设计见 [Scope 设计文档](scope/scope_design.md)。本功能作为新增实时采集能力设计，具体复用范围在实现前结合当前代码确定。

上位机复用顶部公共连接发送所有控制命令，沿用选定设备地址及 E8/E9 协议。ESP32-C5 公共连接可以是 USB Serial/JTAG 虚拟 COM 或 Wi-Fi TCP 5000。独立 Wi-Fi TCP 9001 使用专用 EA 解码器，仅接收数据，不发送控制命令或 E9 协商。两条连接必须对应同一板卡。

设置“数据链路”页提供“搜索设备”，复用顶部以太网搜索弹窗及 UDP 5000 发现协议。ESP32-C5 对完整 `FRAME_DISCOVER_V1` 请求返回设备名称、IP、MAC、固件版本与公共 TCP 5000 信息；示波器选中后使用该 IP 的 9001 端口。其他 UDP 内容继续沿用回显。

两条链路有各自的传输句柄与接收状态，公共控制失联时页面停止采集并提示错误。上位机没有配置/活动通道选择框或“应用配置”按钮，下位机双链表是内部实现。

### 2.1 base 模块隔离与通信注册

实时示波器是 base 的通用调试功能，ESP32-C5 仅提供本次验证用的硬件适配。

| 层 | 文件 | 边界 |
| --- | --- | --- |
| 采样核心 | `code/dbg/realtime_scope.c/.h` | 双链表、采样、EA 编码、有界队列；不依赖 SDK、RTOS、定时器或网络 |
| 控制服务 | `code/dbg/realtime_scope_service.c/.h` | 自持采样对象和固定请求队列；`REG_COMM` 接收控制，`REG_TASK` 管理配置/链表及应答；提供 ISR 采样入口 |
| Demo 接入 | `code/business/demo/demo_realtime_scope.c` | 通过 `REG_INTERRUPT(255, sample_interrupt)` 注册采样；实际应用自行选择注册位置和优先级 |
| Interface | `code/interface/demo/esp32c5/realtime_scope_bindings.c` | 在主任务初始化/任务上下文绑定平台能力，不创建采样器、定时器或网络任务 |
| 平台能力 | `platform/esp32c5/bsp/bsp_system.c` | 短临界区、静态 RAM 地址校验、固件标识 |
| Wi-Fi BSP | `platform/esp32c5/bsp/bsp_wifi_channels.c` | 统一管理控制 TCP 5000 和数据 TCP 9001；取完整包、非阻塞发送、保留部分发送尾部及断线清理 |
| 通用测试 | `tests/host/realtime_scope/` | 编译真实核心和注册服务，验证采样及公共命令边界 |

平台接入时加入两个通用 `.c` 文件，并显式启用业务配置 `REALTIME_SCOPE_ENABLE=1`；默认关闭，不影响其他平台。Interface 在主任务上下文调用 `realtime_scope_service_bind(&binding, queue, capacity)`，提供生命周期覆盖服务的队列存储；服务内部初始化采样对象。控制应用在自身中断初始化后、停止采集时调用 `realtime_scope_service_source_set(actual_hz)`，声明实际固定频率；上位机只查询，不配置。未接入采样源时频率为 0，启动返回状态 5。

公共 COMM 回调复制完整请求到服务内部深度为 4 的静态数组队列；`REG_TASK(1, manage)` 每次最多处理 4 个请求，直接通过原公共链路返回应答。保留 E8/E9 格式及 E9 序号，设置 ACK，交换源/目的地址。没有跨 RTOS 工作任务或应答队列。

采样由 demo 的 `REG_INTERRUPT(255, sample_interrupt)` 注册，回调调用通用服务的 `realtime_scope_service_sample()`，在已有控制 ISR 调用 `section_interrupt()` 时执行；示波器不创建、启停或修改硬件定时器。每次有效调度产生一组真实样本，不能在主循环补采。任务负责配置链表，交换角色前必须停止采样并清空旧队列。Wi-Fi BSP 调用 `realtime_scope_service_read()` 取完整 EA 帧后发送，纯软件不引用 SDK/socket/RTOS；平台回调只提供同步、数据连接状态、固件标识和可读地址校验。连接代数改变时清理旧采集，防止断开后快速重连混入旧帧。

## 3. ELF、MAP 与结构体成员解析

### 3.1 ELF 必选、MAP 可选

自动识别类型和展开结构体，需要 ELF 中保留足够的 DWARF 调试信息，并且目标变量在设备中有可求值的固定内存位置。

| 信息来源 | 主要内容 | 边界 |
| --- | --- | --- |
| ELF 符号表 | 符号名称、地址、大小 | 通常不足以恢复完整结构体布局 |
| ELF 中的 DWARF | 变量类型、类型宽度、成员名称、成员偏移和数组布局 | 优化可能使变量没有可直接采样的位置 |
| MAP | 段布局、符号和地址等链接信息 | 作为辅助核对，通常不能补齐缺失的成员类型与布局 |

ELF 已包含所需信息时，用户无需同时导入 MAP。缺少调试信息时，不能仅依靠 MAP 宣称可以完整展开结构体；第一版应明确提示缺少哪些信息。

### 3.2 参数树与地址计算

FRAME 展示变量树，支持选择全局变量、文件内静态变量、函数内静态变量以及其中的普通成员和固定数组元素。同名静态变量使用源文件、作用域和变量名共同标识。

结构体行可双击或右键展开，通道绑定具体数值成员。混选结构体行与普通成员时，“加入通道”只处理可采样成员，不因父行或其他不支持项禁用整个选区。菜单每次打开重新计算启用状态；不可采样项在参数信息及灰色菜单提示中说明原因。

“指定通道”绑定实际右键点击的成员，独立于多选区首行；菜单关闭后仍保留本次操作的成员，避免指定到父结构体或其他选中项。

成员地址按编译器提供的布局计算：

```text
成员地址 = 结构体对象地址 + 各级成员偏移
数组元素地址 = 数组地址 + 元素索引 × 元素步长
```

以下地址和偏移仅为示例：

| 参数名称 | 地址计算 | 最终地址 | 类型 |
| --- | --- | --- | --- |
| motor | 结构体基地址 | 0x20001000 | Motor |
| motor.speed | 基地址 + 0x04 | 0x20001004 | float32 |
| motor.pi.kp | 基地址 + pi 偏移 0x10 + kp 偏移 0x04 | 0x20001014 | float32 |

成员偏移包含编译器产生的对齐填充，不能根据字段声明顺序手工累加类型宽度。

### 3.3 第一版范围

| 类别 | 支持策略 |
| --- | --- |
| 全局及静态存储期变量 | 具有固定可读地址时支持 |
| 嵌套结构体普通成员 | 按各级成员偏移解析 |
| 固定数组元素 | 按实际元素布局与合法索引解析 |
| typedef、枚举 | 解析到底层编码、大小及符号性 |
| 普通栈变量、寄存器变量 | 第一版不支持地址连续采样 |
| 被优化掉的对象 | 标记为不可采样 |
| 指针 | 可采样指针本身；第一版不自动跟随指针 |
| 位域 | 后续定义存储单元、位偏移、位宽与符号扩展后支持 |

第一版建议支持 int8、uint8、int16、uint16、int32、uint32、float32。64 位整数和 float64 按设备能力增加支持。

协议字节定义为 8 位 octet。目标地址单位、目标类型大小、字节序及浮点表示由设备能力和编译信息确定，不能假设所有平台的 int 宽度或可寻址单位相同。对特殊地址模型的平台，由适配层完成目标地址与传输字节的映射。

### 3.4 固件与访问校验

建议设备返回与构建产物关联的固件标识，并与加载的 ELF 核对。设备不具备可靠标识时，FRAME 必须显示匹配状态未验证。

下位机必须检查完整读取区间是否落在允许采样的内存范围内，检查地址溢出、长度、对齐和支持类型。默认排除会产生读取副作用的外设寄存器。

## 4. 通道描述与链表

### 4.1 固定 32 槽位与下发字段

FRAME 只维护一套 32 槽位驻留通道列表。下位机内部使用两套独立的节点数组及链表；增加、替换或移除参数立即下发到配置链表。“参数同步”先停止，再清空配置链表，按通道号发送完整列表；点击运行时才交换角色指针。设置节点仅下发以下三个业务字段：

| 字段 | 职责 |
| --- | --- |
| channel_no | 通道号，范围 1～32 |
| address | 目标变量或具体成员的数据地址 |
| type | 数据类型编码，唯一确定传输编码与长度 |

设备先检查 `1 <= channel_no <= 32`，再执行 `array_index = channel_no - 1`，禁止先相减或访问数组后检查。通道 33 已经越界，不是有效通道。

每个通道号固定对应当前配置存储中的一个数组元素，即 `p_config.nodes[channel_no - 1]`，不从任意空闲槽位重新分配。重复下发相同通道号表示更新配置槽位，不新增节点，也不修改当前活动链表。

完整参数名称、源文件、成员路径、显示倍率、偏置、单位、颜色和主机解码偏移保存在 FRAME；它们不进入下位机节点。读取长度由类型表查询，节点不保存独立 length 或 offset 字段。

### 4.2 两套存储、节点与有效状态

```text
storage_a：nodes[32]、valid_mask、p_head、数据区长度等配置状态
storage_b：nodes[32]、valid_mask、p_head、数据区长度等配置状态

初始角色：
    p_active → storage_a
    p_config → storage_b

每个节点只有：
    address    数据地址
    type       数据类型
    p_next     下一有效节点的指针
```

每套存储在节点数组之外各自维护一个 32 位有效槽位位图 valid_mask：bit0 对应通道 1，bit31 对应通道 32。位图属于该套配置上下文，不增加节点字段。

不使用 address=0 表示空槽位，避免将地址值与有效状态混淆。初始化时清空两套位图，所有 p_next 置空，两套链表头为空。

两套配置共预分配 64 个节点描述符，每次最多启用 32 个采样通道。节点指向的业务变量不因此复制。两条链表不能共用同一节点对象，否则修改配置节点的 address、type 或 p_next 会影响正在采样的活动链表。每个 p_next 只能指向所属存储的节点或为空。

### 4.3 按通道号升序连接

例如仅配置通道 1、4、12、32：

```text
通道号：          1             4              12             32
数组下标：        0             3              11             31

p_config.p_head
    → p_config.nodes[0] → p_config.nodes[3]
    → p_config.nodes[11] → p_config.nodes[31] → NULL
```

数组在内存中固定分配，链表串联其中可能不相邻的有效元素。链表顺序始终由通道号决定，不受配置命令到达顺序影响。

每次添加、更新或删除后，只扫描配置存储的 32 个槽位重建配置链表：先清空该套节点的 p_next，再按下标从小到大连接其 valid_mask 中有效的节点，最后一个有效节点的 p_next 保持为空。该操作有固定上限，在后台执行，活动链表可继续采样。

删除命令只需要通道号，清除配置存储对应有效位并重建配置链表；清空命令只清除配置存储的全部有效位。删除后该槽位可以由同一通道号重新配置，不移动其他槽位。提交切换后配置存储暂时只读，新的编辑请求返回忙，直到切换完成或取消。

### 4.4 配置校验与数据布局

启用前核对上下位机待启用配置的有效通道位图与各槽位类型，要求有效通道数为 1～32，空配置不能启用；验证地址、类型、节点归属、链表节点数和链表无环，计算该套配置的单次全通道采样字节数 B，并检查带宽与缓冲容量。正在使用的活动存储始终只读；配置存储从提交切换到完成或取消期间也只读。

上位机按有效通道号升序计算解码偏移。例如通道 1 为 float32、通道 4 为 int16、通道 12 为 uint8，则三个通道的数据偏移依次为 0、4、6，B=7。

下位机核心允许编辑配置链表而不影响活动链表。当前上位机采用单通道列表：修改参数绑定会先停止采集、清理旧波形并立即下发。已知配置链表与驻留列表一致时只更新变化槽位；连接变化、配置状态未知或上次运行已经交换链表时，先清空再重建完整列表，避免修改到旧角色内容。EA 帧没有通道号，新布局必须在新采集段开始前准备好。

采样频率改变也按配置切换边界处理，不能在同一时间段内静默改变时间基准。显示颜色、单位及倍率可由 FRAME 单独调整。

### 4.5 角色互换，不复制节点

在第 11 节定义的切换边界，通过平台同步机制一次提交整套配置上下文的角色交换：

```text
切换前：p_active → storage_a，p_config → storage_b

p_temp   = p_active
p_active = p_config
p_config = p_temp

切换后：p_active → storage_b，p_config → storage_a
```

被交换的是整套存储的角色指针，因此节点数组、链表头、有效位图、数据区长度和其他布局状态随该套存储一起生效。不能只交换两个链表头却仍使用另一套位图或长度。

切换不遍历链表、不复制节点、不复制节点数组、不重新连接待启用链表。交换后，原活动链表原样成为配置链表，原配置链表成为活动链表。未编辑时可再次提交并反向切换。

下位机两套存储不会互相复制。交换后配置链表保留旧内容；上位机每次同步均先清空配置链表并重建完整列表，因此无需跟踪 A/B 存储角色，也不向用户暴露内部角色。交换成功应答返回有效数据字节数，用于核对主机布局。

只交换角色指针并不自动保证中断安全。控制任务不得在中断遍历期间修改活动存储；提交采用适合平台的短临界区或等效同步，保证本次采样退出后再交换，并在下一次采样入口获取新的活动指针。多核目标还需确保没有其他读取者继续引用原活动存储，才可允许其作为配置存储被修改。

## 5. 中断采样与发送缓冲

### 5.1 采样位置与一致性

在控制中断中的固定阶段调用采样入口，例如本周期控制计算完成后。需要通过一致的调用位置保证样本的控制阶段含义。

每次采样入口只取得一次 p_active，并在本次遍历中使用同一套活动存储及其链表，按顺序读取各通道并写入一组紧凑数据。本次采样中途不重新读取角色指针，避免一帧混用两套布局。顺序读取存在少量通道间时间差；若变量会被更高优先级中断、DMA 或其他处理单元更新，必须另行保证数据一致性。

64 位值和多字段组合不默认具备原子快照语义。volatile 不能单独保证跨字段一致性，也不能代替平台同步措施。

### 5.2 中断内职责

- 判断运行状态及本次是否达到分频采样时刻。
- 读取本次固定的活动链表，将原始值复制到采样缓冲；中断不编辑配置链表。
- 每次全通道采样产生一帧需要的数据，数据包 index 按模 256 递增。
- 将完整帧或采样记录发布给发送流程，可将若干独立帧聚合到一个发送块，并切换到可写缓冲。
- 缓冲耗尽时锁存溢出原因，停止本次示波器采集并留下可查询状态。

中断内不进行堆分配、字符串格式化、工程量浮点换算或阻塞式通信。后台发送流程计算帧校验并提交传输；若计算或硬件提交需要位于中断内，必须先证明最坏耗时满足预算。

### 5.3 所有权与溢出

缓冲块按“空闲 → 填充 → 待发送 → 发送中 → 空闲”流转。DMA 仍在使用的块不能被采样端覆盖；发布和回收必须使用适合目标平台的同步机制。

采样阶段将值写入独立数据缓冲，发送阶段只使用该缓冲及其已确定的帧布局，不在发送时重新遍历当前活动链表。角色切换也不能使旧帧按新长度封装。旧帧及 DMA 引用处理完成前，不进入新配置的数据流。

默认采用溢出后停止本次采集的策略，不等待通信、不阻塞控制中断。设备保留停止原因、溢出次数和采样统计供控制路径查询，不能继续发送却隐瞒未采集的周期。

缓存、队列及待发送块数量均有明确上限。设备不负责保留 10 秒历史，该历史容量属于 FRAME。

## 6. EA 数据协议

### 6.1 帧格式与数据长度

```text
EA(1 B) + index(1 B) + 数据1 + … + 数据N + data_len(暂定2 B) + checksum(1 B)
```

N 为当前有效通道数，范围 1～32。每帧包含全部有效通道在同一个采样调用中的一次读取结果，数据顺序为有效通道号升序。未启用通道不占数据区空间，也不填零补位。

设 B 为全部有效通道的传输长度之和，按 data_len 暂定 2 字节计算：

| 字段 | 偏移 | 长度 | 含义 |
| --- | ---: | ---: | --- |
| head | 0 | 1 B | 固定 0xEA |
| index | 1 | 1 B | 数据包计数，模 256 递增 |
| data | 2 | B | 按有效通道升序拼接的原始采样数据 |
| data_len | 2 + B | 2 B | 仅 data 区字节数，不含帧头、index、长度字段和校验和 |
| checksum | 4 + B | 1 B | 从帧头到长度字段末尾的逐字节累加和低 8 位 |

```text
B = sum(type_width(各有效通道.type))
data_len = B
总帧长 = B + 5
```

多字节整数统一使用小端序，浮点数据采用协商支持的明确编码。不直接发送带编译器填充的内存结构体。data_len 的字段宽度是当前暂定值；本协议不加入额外会话或绝对采样计数字段。

### 6.2 非连续通道的数据示例

配置通道 1 为 float32、通道 4 为 int16、通道 12 为 uint8，其他槽位未启用：

```text
链表：nodes[0] → nodes[3] → nodes[11] → NULL

数据帧：
EA | index | CH1(4 B) | CH4(2 B) | CH12(1 B) | 07 00 | checksum
```

此处“数据1、数据2、数据3”表示第 1、2、3 个有效通道的数据，其原始通道号分别是 1、4、12，不代表连续的槽位号。FRAME 依当前有效通道表将三个数据值分别填入 CH1、CH4、CH12 并绘图。

### 6.3 累加校验和

本文暂按实际帧头 EA 作为累加起点，逐字节累加到 data_len 的最后一个字节，取低 8 位，不取反，也不包含 checksum 本身：

```text
checksum = (0xEA + index + sum(data各字节) + len_low + len_high) & 0xFF
```

两个长度字节分别参与累加，不能将 16 位长度数值作为一个整体替代它们的字节和。

示例：仅启用一路 uint8，index=0，采样值=0x12，data_len=1：

```text
EA 00 12 01 00 FD

FD = (EA + 00 + 12 + 01 + 00) & FF
```

该校验是用户指定的 1 字节累加和。它不能检测所有字节交换或相互抵消的错误，文档不承诺所有传输错误都可被检出。

### 6.4 尾部长度与接收分帧

由于长度字段位于数据区后面，FRAME 必须先根据已确认的通道配置算出 B，才能定位长度和校验字段。尾部长度用于核对当前配置，不能用于在未知配置下预先定位帧尾。

解析步骤：

1. 从接收缓冲搜索 0xEA。
2. 按当前 B 等待 B+5 字节，设置候选帧等待超时和总接收缓冲上限。
3. 读取偏移 2+B 处的 2 字节长度，要求等于 B。
4. 验证累加和；通过后再检查 index 连续性并按通道类型解码。
5. 有效帧整体消费 B+5 字节，数据中的 EA 不另起一帧；候选失败时从该候选起点的下一个字节继续搜索。

不能假设一次串口、USB 或网络读取恰好对应一个完整帧。接收流程支持分包和粘包；配置不匹配时不猜测通道类型或数据长度。

### 6.5 index、回绕与时间缺口

每次新采集启动时 index 从 0 开始，每形成一个完整采样帧递增一次，255 后回到 0。发送层可聚合多个完整帧，但不得省略帧内 index、长度或校验和。

FRAME 计算 `delta = (index_current - index_previous) & 0xFF`。只有在已排除重复、倒序并能约束丢包数量的条件下，才能用 delta 推算前进的采样间隔；不能从 1 字节 index 唯一识别额外整 256 帧的缺失。

30 kHz 且每帧一次采样时，index 约每 8.53 ms 回绕。delta=1 既可能表示相邻帧，也可能隐藏额外整 256 帧缺失，不能把单次回绕检查作为绝对无丢包证据。

FRAME 在连续性可确定的范围内维护较宽的逻辑采样计数，并按可识别的缺口留空。遇到长时中断、来源不明或回绕歧义，标记时间连续性未知，结束当前连续段并停止或重新同步采集，不伪造精确的缺失时长。

实时数据默认不重传。设备停止采样、缓冲溢出或复位时结束本次采集，不暂停若干周期后继续发送却隐藏时间缺口。

### 6.6 控制协议与兼容

控制通过顶部公共 E8/E9 的 `cmd_set=0x01 / cmd_word=0x3A`。请求 payload 为 `command:u8 + transaction:u16LE + data`，应答为同样 command/transaction 加 `status:u8 + data`，status=0 为成功；外层沿用公共协议长度及校验。直接应答设置 is_ack=1 并保留 E9 序号。一个客户端同时仅一个待应答请求，默认 5 秒超时，不自动重发切换或启动。独立 TCP 9001 只发送 EA，收到任何应用数据即关闭连接。

| command | 请求与成功应答数据（不含 status） |
| --- | --- |
| 1 能力 | 无请求数据；应答 version:u8=1、channels:u8=32、max_hz:u32、byte_budget:u32、ELF SHA256:32B、sample_hz:u32；新增实际采样频率在尾部，旧 max_hz 字段保留并等于固定频率 |
| 2 停止 | 停止示波器采样使能、关闭旧数据连接、丢弃未发送尾部及样本队列，保留两套链表；外部控制中断继续运行 |
| 3 清空 | 清空配置链表，活动链表保持独立；成功应答追加当前 sample_hz:u32 |
| 4 设置 | slot:u8、type:u8、address:u32；address=0 删除该槽，否则校验静态 RAM 范围及对齐；成功应答追加当前 sample_hz:u32，0 表示尚未接入采样中断 |
| 5 切换 | 仅在已停止且队列为空时交换两个 bank 指针；应答活动 payload_size:u16，尾部追加当前 sample_hz:u32 |
| 6 开始 | 无请求数据；应答下位机固定 frequency:u32 Hz；index 从 0 开始。兼容旧请求的 4 字节频率仅用于一致性检查，不改变定时器，值不匹配则拒绝 |
| 7 状态 | running:u8、samples:u32、overflows:u32、queue_count:u32、timing_fault:u32、data_connected:u8、link_fault:u32；尾部追加 queue_high_water:u32、dequeued:u32，旧字段位置不变 |

所有多字节整数为小端。状态 1=字段不足、2=通道/地址/类型非法、3=切换/运行状态不允许、4=频率或带宽超限、5=采样源未接入、6=未知命令、7=请求队列忙或服务尚未绑定。类型码依次为 1/i8、2/u8、3/i16、4/u16、5/i32、6/u32、7/i64、8/u64、9/f32、10/f64、11/bool。64 位整数绘图转换为 double，超过 53 位有效精度时不能作为逐位精确数值查看器。

transaction 用于匹配同一操作的应答，E9 同时核对外层序号。当前控制命令不自动重试；超时后停止本轮操作，下次配置重新执行停止、清空、完整下发、交换，不能单独重发交换。设备在 SECTION 主任务中处理公共 COMM、静态请求队列、配置及链表；已有控制 ISR 经 SECTION 的中断注册链采样入队；Wi-Fi BSP 在同一主任务中维护 TCP 并有界发送。

串口沿用现有参数、Shell 与 Perf 设置链路，ESP32-C5 当前串口实现为板载 USB Serial/JTAG 虚拟 COM；没有在本次新增物理 UART 引脚配置。公共 Wi-Fi TCP/UDP 5000 与示波器 TCP 9001 分开。示波器首版使用 STA 接入现有 Wi-Fi，网络信息沿用平台私有配置构建流程。

控制协议不设置推测性的 reserved 字段；已发布字段顺序和含义保持稳定，兼容字段在末尾追加。固定控制 payload 按收到的长度与本地结构大小取小解析，缺少的可选字段采用明确默认值；必需字段缺失则拒绝执行。

ACK 仅表示对同一 cmd_set / cmd_word 请求的直接响应。EA 连续数据和异步状态上报不因启动命令而自动视为 ACK。

EA 数据区具有明确的全通道布局，不能通过任意截断 payload 来兼容不同配置。配置链表可以在活动采样期间编辑；真正启用时按第 11 节停止并关闭旧数据连接、交换角色并同步 FRAME 解码布局，建立新的采集段。

## 7. 频率设置与时间轴

### 7.1 四种频率分别表达

| 参数 | 示例 | 含义 |
| --- | --- | --- |
| 控制中断频率 | 30 kHz | 采样入口的调用基础 |
| 实际采样频率 | 30 kHz | 每个通道每秒的采样次数 |
| 被测信号频率 | 50 Hz | 波形测量结果 |
| 绘图刷新率 | 30 Hz | 屏幕更新速度 |

采样频率由下位机固件固定，上位机通过公共通信接收 Hz 值并显示换算周期。清空、设置通道和交换配置的成功应答都附带当前采样率；增加通道和“参数同步”收到应答后立即更新显示，不做周期性轮询。能力查询用于固件身份及上限检查，旧固件未扩展配置应答时可使用能力应答中的频率。连接变化后显示“待同步”，不沿用旧设备频率。0 Hz 表示未接入采样中断，允许编辑配置，禁止启动采样。设备模式不提供频率设置，修改频率需在下位机配置采样源并重新验证。

建议采样频率使用有理数 Fs = F_num / F_den 表达。协议字段宽度应覆盖目标时钟与分频范围，计算中检查溢出和分母为零。

第一版优先支持从基础中断做整数分频；无法精确实现请求值时，在启动前返回实际频率，界面明确显示差异。抽点降采样不等于已经进行抗混叠滤波。

### 7.2 时间由序号直接计算

```text
t(n) = (n - n0) × F_den / F_num
```

缓存保存 FRAME 扩展的整数逻辑采样序号和本次采集的实际频率，显示时再转换成秒。序号只能在第 6.5 节所述连续性可判定的范围内扩展；跨越未知缺口时建立新的相对时间段。不能逐点累加取整后的微秒周期，也不能使用主机收包时间代替采样时间。

30 kHz 对应周期为 33.333333… μs，30,000 个采样间隔为 1 秒；逐点累加 33 μs 会得到 0.99 秒，每秒引入 10 ms 的取整累计误差。

该设计消除数值取整造成的累计漂移。硬件时钟偏差、中断执行抖动和通道间读取时间差仍需测量，不由时间轴公式消除。

## 8. 通信预算与设备缓存

### 8.1 带宽公式

设 Fs 为实际采样频率，B 为一次全通道采样的字节数，H 为每帧固定开销。当前每帧一次采样，data_len 暂定 2 字节时 H=5：

```text
R_sample = Fs × B
R_wire = Fs × (B + H)
```

UART 8N1 每字节占 10 个线路位：

```text
baud_min = 10 × R_wire
链路利用率 = 10 × R_wire / baud_actual
```

预算应使用实际波特率和全部协议开销。USB、以太网等链路按持续有效吞吐、底层封装与实测停顿计算，不直接使用标称接口速率。

### 8.2 算例

采用当前帧格式，H=5 字节，Fs=30,000 Hz，每帧一次全通道采样；表中 kB/s 使用十进制单位。

| 通道配置 | B | 纯采样数据率 | 含 EA 协议的数据率 | UART 理论最低波特率 |
| --- | ---: | ---: | ---: | ---: |
| 4 路 float32 | 16 B | 480 kB/s | 630 kB/s | 6.30 Mbaud |
| 8 路 float32 | 32 B | 960 kB/s | 1,110 kB/s | 11.10 Mbaud |
| 32 路 float32 | 128 B | 3,840 kB/s | 3,990 kB/s | 39.90 Mbaud |

建议初期持续链路利用率上限设为 70%，并通过实际硬件验证调整。8 路 float32、30 kHz、12 Mbaud 的利用率约为 92.5%，超过该预算；20 Mbaud 时约为 55.5%。固定支持 32 个槽位不代表任意链路都能以 30 kHz 上传 32 个通道。

FRAME 与设备都校验预算。超过能力时拒绝启动，提示减少通道或使用更窄的数据类型，不能改变下位机固定采样频率来迁就带宽。

### 8.3 分包延迟与缓冲容量

每次全通道采样形成一个独立帧。发送层可以将 32 个完整帧聚合到一次 DMA 或驱动提交，在 30 kHz 下积攒时间约为 1.07 ms；这种聚合不减少每帧的 5 字节协议开销。实际端到端延迟还包括发送排队、链路、主机接收与绘图刷新。

设备缓冲的初始估算为：

```text
M_device >= R_wire × T_stall
```

还需计入填充中、排队中和 DMA 占用块的空间，按实际缓冲布局分配，避免重复计算或遗漏。T_stall 是设计允许吸收的链路停顿时间，不表示可以吸收任意长停顿。

## 9. FRAME 缓存、线程与绘图

### 9.1 数据所有权

接收与解码流程批量写入后端环形缓存；UI 通过有界批量接口或稳定快照读取，不能持有会被后台覆盖的可变数组引用。

原始数据使用二进制批量传递，避免逐点跨语言调用、逐点 JSON 对象及 UI 线程中的分帧处理。可在 UI 落后时跳过过期显示任务，不能因绘图落后阻塞接收。

### 9.2 10 秒环形缓存

```text
每通道容量 N = ceil(Fs × T_history)
```

默认 T_history=10 秒，可在启动前配置，并检查总内存上限。缓存满后覆盖最旧数据。

8 路 float32、30 kHz、10 秒的原始采样值占用约 9.6 MB；全部转成 double 时，仅数值数组约 19.2 MB。32 路 float32 在相同条件下分别约为 38.4 MB 和 76.8 MB，另需计入缺口、索引和显示缓冲。

建议保留原始类型，以主机维护的逻辑采样序号和频率隐式表达段内时间，并以有界段信息记录缺口及未知连续性。64 位整数在转换为 double 显示时可能损失精度，精确读数应保留原始值。

实时数据不自动落盘，原始流也不能通过调试日志形成隐式持续保存。停止后可在当前进程内查看保留数据。

### 9.3 绘图与测量

绘图按当前窗口像素宽度生成最小值/最大值包络，保留尖峰。放大后读取缓存细节；包络不跨数据缺口聚合。

测量使用缓存中的完整有效样本，不用缩减后的绘图点计算。缺口处断线，跨缺口的周期、RMS 或频率测量必须显示无效或明确提示有效覆盖范围。

## 10. 示波器界面与操作

### 10.1 页面与参数加载

FRAME 导航中新增“实时示波器”。多个通道在单个波形窗口叠加显示，横向 10 格、纵向 8 格；各通道独立量程和位置。布局及常用操作优先参考用户习惯的周立功 ZDS 系列，功能概念参考大厂官方资料；主题、配色和控件沿用 FRAME，不复制厂家皮肤或默认分行显示。界面只保留按钮、数值、单位和简短状态，操作说明放帮助文档。

主页面包含紧凑操作栏、采集、触发、数据链路、波形、通道和侧边读数；不显示大标题和设置按钮。按钮高 28 px，常用按钮最小宽 72 px，输入框及下拉框同高。标签与字段成组，按可用宽度紧凑换行，不让每个功能组独占整行而留下大片空白。量程只在通道表编辑，窗口滚轮只缩放时间。“选择参数”保持弹窗，ELF/MAP 路径不常驻。

当前主页面分区按以下方式落实，不在波形底部重复放通道：

| 区域 | 内容 |
| --- | --- |
| 操作栏 | 运行/停止、冻结/继续、单次、自动设置、选择参数、参数同步及简短状态；按钮使用中文，无设置按钮 |
| 采集栏 | 数据源、只读采样率、缓存时长、窗口总时长；设备采样率由公共链路查询，连接后及运行前核对 |
| 触发栏 | 实时、模式、触发源通道、上升/下降沿及冻结选项；电平与触发位置通过游标拖动调整，窗口滚轮只缩放时间轴 |
| 波形区 | 单窗口多通道叠加；保留网格，纵轴无公共数字刻度或 div 标题 |
| 侧边面板 | 通道名称、单位、量程和显示开关；游标及测量读数，X1/X2 各占一行 |

主页数据链路行提供搜索设备、IP、TCP 端口、连接/断开及本页 RX/TX 计数，不再保留设置弹窗。输入框、按钮、下拉框统一 28 px 高度和间距，窄窗口按行排列。当前 ESP32-C5 连接 Wi-Fi TCP 9001，顶部公共连接用于全部控制及原有参数功能。符号解析、数据接收与公共通信各自拥有独立后端上下文。

ELF 参数加载复用原生符号索引能力，并使用本页独立的符号解析上下文，避免覆盖 J-Link 页的已加载符号。加载与展开普通结构体、数组成员不连接探针，也不读取设备内存。

参数支持结构体成员展开和已加载名称搜索。右键“加入通道”按 CH1～CH32 顺序加入首个空槽位，多选时按参数列表顺序处理；右键“指定通道”可设置或替换指定槽位。不提供拖放加入。整个结构体、指针、不支持的位置表达式及重名歧义变量不能直接采样。

每次点击主页面或弹窗中的“选择参数”，都释放旧符号上下文并从硬盘重新建立 ELF 索引，同一路径也不复用内存索引。读取前后核对 ELF/MAP 内容指纹，读取期间发生编译更新则失败重试，不提供旧列表。MAP 可选；没有 DWARF 或类型不明时不根据名称猜测类型。

重新读取保留驻留通道及显示设置。文件内容变化后标记“待同步”，停止当前预览、清理旧波形并阻止使用旧绑定启动采集；由“参数同步”重新定位参数，不自动将旧地址视为当前固件地址。

### 10.2 通道与独立单位缩放

通道号、参数名称、单位、每格量程及波形显示开关放在侧边通道表。单位和 `/div` 直接在对应行编辑，不显示右下角“独立显示设置”，波形底部不重复显示通道栏。

| 功能 | 预期行为 |
| --- | --- |
| 通道选择 | 唯一的 CH1～CH32 列表，加入参数立即可见；修改绑定时停止当前采集 |
| 参数同步 | 从磁盘重新读 ELF，并经公共链路完整配置下位机，内部双链表由设备管理 |
| 开始 / 停止 | 控制设备采集与上传 |
| 冻结显示 | 固定观察窗口，后台继续接收 |
| 返回实时 | 跟随最新数据 |
| 水平缩放与平移 | 调整时基并浏览缓存 |
| 垂直缩放与平移 | 每通道独立设置单位、每格量程和位置；量程可直接输入或悬停滚轮调整，只影响所选通道 |
| 时间及幅值游标 | 读取值、Δt、Δy 和 1/Δt |
| 自动测量 | 最大值、最小值、峰峰值、均值和 RMS |
| 周期测量 | 频率、周期和占空比；有效周期不足时提示无效 |
| 触发 | 小窗口使用自动/普通触发，支持边沿、电平和预触发比例；单次为独立按钮，滚动模式不触发 |
| 自动设置 | 根据已捕获数据调整量程、位置、触发源中点及约三个周期的时间范围 |
| 参数选择 | 弹窗内右键加入；每次选择均重新读取磁盘 ELF |
| 参数同步 | 重新定位驻留参数，保持通道号和显示设置，设备确认后启用新布局 |

每个通道单独维护以下显示参数，与设备读取的原始类型和地址分离：

| 参数 | 含义 |
| --- | --- |
| 单位 | 默认空；可选 V、A、W、var、VA，也可输入自定义文字或留空 |
| 每格量程 | 该通道一个纵向格对应的工程量，必须为正数 |
| 位置 / div | 通道的垂直显示位置，以格为单位 |
| 倍率 | 原始值到工程值的乘数 |
| 偏置 | 原始值换算为工程值时的加数 |

```text
工程值 = 原始值 × 倍率 + 偏置
纵向格数 = 工程值 / 每格量程 + 位置
```

例如 CH1 为 10 V/div、CH2 为 0.5 A/div，两条曲线共用窗口，各自独立缩放。纵向保留网格，不显示公共数字刻度或 div 标题。侧边通道面板显示各自名称、单位和量程，Y 游标按所选通道换算工程量。波形底部不设置通道栏。

每格量程直接在侧边通道表的 `/div` 单元格编辑，不在顶部重复。数字框支持任意正有限值，回车或失焦提交；悬停滚轮按 1/2/5 档位增减，向上增大量程、向下减小，不要求键盘焦点。每个通道分别累计高分辨率滚轮刻度；滚轮事件由数字框消费，不传递到时基缩放。单位同样在通道表编辑，无效量程不覆盖有效值，不影响其他通道或原始数据。波形窗口提前消费滚轮事件，仅修改显示时间范围，禁止绘图库默认的纵轴滚轮缩放；所有通道量程及纵轴范围保持不变。

例如选中 CH1 后输入 0.25，表示每格 0.25 个工程单位；若单位为 V，则为 0.25 V/div。滚轮向上进入下一档 0.5，随后向下进入 0.2。直接输入不强制吸附到 1/2/5 档位。切换到 CH2 后，数字框显示 CH2 自己的量程，CH1 保留此前值。

界面按通道号保存唯一列表的参数绑定与显示设置；参数同步只更新地址和类型，保持单位、量程及位置。绑定变化时停止采集，显示设置允许随时修改。

通道表移除单位列，保留参数名称与可编辑的 /div 数值。空单位表示按纯数值显示，图例、光标与触发电平均不自动补上 V 或其他单位；每格量程仍正常生效。

### 10.3 显示时长、历史容量与触发暂停

先区分基本概念：时基为每格时间，10 格窗口的显示时长为时基×10；采样率为每秒样本数，样本间隔为其倒数；历史容量为缓存覆盖时长，不等于可见窗口。缩放不改变约定采样率，时间仍按样本序号/频率计算。历史容量默认 10 s，可见窗口默认 100 ms。

产品按可见窗口**总时长**切换：≥500 ms 固定滚动模式，不使用触发；<500 ms 使用自动或普通模式，恢复之前选择，初始为自动。恰好 500 ms 归滚动。这是 FRAME 的产品阈值，不作为所有示波器的通用规则。

滚动模式追加样本、图像向左推移，触发源、边沿及触发按钮禁用，强制触发无效，单次按钮不可用；触发游标保持可见、可拖动，预调参数供小窗口使用。缩回小窗口后恢复触发控制。跨阈值清除旧画面及捕获状态，避免旧触发帧误认为新滚动数据；同一模式内手动冻结后缩放保持冻结。

启用触发后选择活动通道、边沿及工程电平，预触发位置可设 0～100%，默认 50%。触发捕获以触发时刻为 t=0，不绘制黄色触发竖线。倍率为负时对应反向原始边沿，倍率为零时拒绝该触发源。

触发电平用右侧三角形内的 T 表示，三角累计顺时针旋转 90°、尖端向左，竖边贴着绘图区右边框，T 字正向。静止时只显示标记，拖动时显示水平参考线，释放鼠标后隐藏横线。位置随触发源的独立量程换算，拖动更新工程电平；顶部三角标记拖动更新预触发比例。运行及滚动模式保留两种标记，滚动时拖动仅预调触发参数，不启用触发等待。主页移除电平和位置百分比数字输入框。

小窗口中“触发后冻结”为可选显示行为，放在主页触发栏，默认关闭，使普通/自动模式正常重复显示。主动开启后完成一帧触发捕获才冻结显示，接收继续；不能把它当作普通模式的定义。

冻结仅影响显示，接收和环形缓存继续运行。保留当前窗口完整采样快照，原始环形缓存覆盖后仍能计算游标和测量，并调整纵向缩放。继续 或 重新触发 恢复等待触发，不自动写入磁盘。

真实采集与模拟源共用 FRAME 缓存触发，模式如下：

| 模式或操作 | 行为 |
| --- | --- |
| 滚动 | 可见窗口 ≥500 ms；无触发连续推移，不允许单次捕获 |
| 自动 | 命中时显示完整触发窗口；无命中超过 max(100 ms, 一个窗口) 后自由刷新 |
| 普通 | 等待触发并收齐后触发部分才更新；无命中时保留上一捕获或等待空画面 |
| 单次按钮 | 可见窗口 <500 ms 时的一次捕获操作，不放在自动/普通模式选择框中；完整捕获后停采，样本计数停止 |
| 强制触发 | 忽略当前电平交叉条件，强制产生一次触发并补齐后触发数据 |
| 运行 / 停止 | 启动或停止采集；与单独冻结显示区分 |
| 自动设置 | 用保留的原始采样数据分别适配所有已绑定且可见通道的量程和位置，量程选 1/2/5 序列；按最慢的可见周期显示约三个周期，受采样分辨率和历史容量限制；无有效周期时保持时间窗口；隐藏通道不参与，不改采样率或原始点位 |

X1/X2 为时间游标，Y1/Y2 为幅值游标，四条实线可独立开关、拖动、复位。侧边显示 X1、X2、ΔX、1/|ΔX| 以及参考通道的 Y1、Y2、ΔY。每个 X 游标单行显示游标时间和最近原始样本值，不重复列第二个时间；Y 按量程和位置反算工程值，超出快照时显示无数据。

自动测量提供最大、最小、峰峰值、均值、RMS、频率、周期、占空比及样本数。测量基于当前完整采样快照，不使用抽稀绘图包络。频率及占空比为窗口幅值中点交叉估计，至少需要两次上升沿；直流、周期不足及非有限数值显示无效。不能把该估计当作已验证的硬件频率计。

状态区显示查询到的实际采样频率、对应周期、有效通道数及 32 槽位使用情况、通信预算与预计带宽。接收及状态接口提供吞吐、缓冲水位、可识别的包间缺口、累加校验错误和设备停止原因。未连接或尚未查询时显示“采样率待查询”，不把旧缓存值冒充当前设备频率。

### 10.5 固件升级后的参数同步

驻留通道保存参数完整名称及当前地址、类型，不能只保存裸地址。固件升级会丢失设备通道链表，并可能改变静态变量地址或成员布局；主机不能因驻留通道仍存在就假定设备已经配置。

“参数同步”流程：

1. 停止采集，保留通道号、参数完整路径和显示设置，重新从磁盘读取当前 ELF/可选 MAP。
2. 按完整名称重新定位根变量、嵌套结构体成员及固定数组元素，校验重名歧义、地址及标量类型；数组按索引定位，指针不自动解引用。
3. 先完成全部驻留参数的解析，任一失败则整批拒绝，不部分覆盖，不沿用找不到参数的旧地址。
4. 主机一次性替换新地址、类型及宽度，保持稀疏通道号、通道顺序、单位、量程和位置；清理旧波形，生成活动配置待下发清单。
5. 通过顶部公共通信链路查询设备状态及固件标识，重建配置链表；逐项下发通道号、地址和类型，设备校验长度、带宽和可访问范围。
6. 收齐配置应答并更新设备返回的采样率后显示“已同步”；配置仍驻留在配置链表中，点击运行才按第 11.2 节交换、核对长度并开始真实采集。采样率为 0 时可以同步但不能运行。

本版已实现上述链路；本地 ELF 全文件 SHA256 必须与设备 esp_app_desc 中的 app_elf_sha256 相同。启动还检查磁盘内容是否与当前符号索引一致，路径相同但文件已更新时阻止使用旧绑定，要求参数同步。连接成功或本地地址解析成功均不视为设备同步成功。

## 11. 控制流程与异常处理

### 11.1 启动流程

```text
连接设备 → 查询能力与固件标识 → 导入 ELF / 可选 MAP
→ 选择通道 → 配置频率、链路与缓存时长
→ 下发到配置链表 → 设备校验并返回实际参数
→ FRAME 核对待启用的 32 槽位配置与实际参数
→ 清理旧链路数据和接收状态 → 交换活动与配置角色
→ 启动 → index 从 0 计数 → 按新活动布局显示 → 停止
```

启动使用设备确认后的活动参数。配置编辑、校验、角色切换和启动属于不同控制步骤，设备尚未确认切换时不能按待启用参数直接解码。

### 11.2 状态与配置切换

上位机只有一份驻留通道，下位机保留配置与活动两条链表。数据帧不含配置编号，采用新的 TCP 连接隔离采集段，不能将公共链路 ACK 当作旧数据已到达主机的证明。

1. 修改通道绑定时停止当前采集，主机清理旧波形；显示单位及量程调整不停止采样。
2. 同步或运行时，经公共链路发送停止；设备关闭示波器采样使能和旧数据连接，丢弃未发队列和部分发送块，保留通道节点，已有控制中断继续运行。
3. 通道编辑立即更新配置链表；“参数同步”清空并重建完整列表。收齐应答并更新采样率后结束同步，不交换角色。
4. 点击“运行”时等待配置完成；配置尚未启用则交换两条链表指针并核对 payload 字节数，节点内容无需复制。重新连接 TCP 9001，经公共状态查询确认 data_connected。
5. 主机准备对应解码布局并清空新采集缓存，经公共链路发送开始；设备仅在数据连接就绪时允许启动，index 从 0 开始。

停止时允许丢弃尚未到达主机的尾部，已接收数据保留在停止观察窗口中。换通道及再次运行建立新采集段，不将暂停时间拼成等间隔样本。任一步失败均不继续启动，不单独重发交换；下次操作重新完整配置。

### 11.3 异常策略

| 异常 | 处理 |
| --- | --- |
| 地址、类型或配置非法 | 拒绝配置，给出具体通道及原因 |
| 带宽或缓冲预算不满足 | 拒绝启动，返回限制 |
| 待启用配置校验失败 | 不交换角色，活动链表继续使用原配置 |
| 切换提交后继续编辑 | 返回忙，不修改已锁定的配置存储 |
| 排空或切换握手超时 | 暂停本次切换并报告实际角色，不混用新旧布局 |
| 累加校验失败或字节失步 | 按确认的 B 重新同步，统计错误，不把未校验数据入库 |
| 包缺失 | 在 index 能判定的范围内保留缺口；整 256 帧等歧义标记连续性未知，不重传追赶 |
| 设备缓冲溢出 | 停止本次采集，锁存原因，控制流程继续运行 |
| FRAME 绘图落后 | 合并显示任务，继续有界接收与缓存 |
| 设备复位或链路断开 | 结束当前会话，显示中断，重新握手 |
| 异步上报无法送达 | 下次状态查询仍能读到锁存原因 |

| 实时落盘 | 关闭 | 不自动保存采样流 |

验证平台使用现有 ESP32-C5：顶部公共连接为 USB Serial/JTAG 或 TCP 5000，独立数据连接为 TCP 9001。GPTimer 以 1 MHz 计数，使用绝对期限及余数分配避免累计舍入误差；10 kHz 对应 100 tick。30 kHz 的 33/34 tick 分配仅说明时间算法，本次板卡未通过该频率。检测到下一期限已过即锁存 timing_fault 并停止，不补造历史采样。采样核心由平台链接映射放入 IRAM，定时器中断优先级为 3，启用 GPTimer 的 IRAM 控制及缓存安全配置。

队列按实际帧长紧密存储于 64 KiB 字节环形缓冲，每帧最多 261 B。发送任务有界聚合完整帧并保留部分发送尾部。ESP32 适配器当前能力上限为 10000 Hz、1000000 B/s；频率同时受当前帧长约束。3 路 4 字节通道在 10 kHz 下为 170000 B/s，32 路 4 字节通道在 5 kHz 下为 665000 B/s；32 路 10 kHz 超预算而拒绝启动。这些是 EA 应用字节率，不包含网络协议开销。

ESP32 可读范围限当前 ELF 的 _data_start 到 _bss_end 静态 RAM，拒绝外设、Flash 常量、PSRAM、RTC 与任意指针解引用；其他平台自行实现地址规则。多通道逐项读取及 64 位变量读取不保证应用级原子快照，需一致性时由业务代码发布稳定观测副本。仍需单独验证长期运行、ISR 最坏耗时和 Wi-Fi 最坏停顿；双链表角色直接互换、升序采样和 EA 帧格式不随平台改变。

### 15.2 固定采样率与 8 通道吞吐优化

本节为旧版已烧录固件的实测记录，包含后续已移除的 GPTimer 专用中断实现；SECTION 重构后的接入方式及验证边界见 15.3。

ESP32-C5 固件采样频率固定为 31250 Hz，即 32 μs。整数周期采用 GPTimer 自动重装，ISR 只采样入队并检测时间异常；周期与超时阈值在启动前计算。Wi-Fi 关闭节能，TCP 发送缓冲增至 41760 字节、发送聚合窗口增至 32，发送批次按实际帧长填充，严格不超过 BSP 单次 2048 字节限制。通用控制服务继续由 `REG_COMM(01, 3A, ...)` 注册，平台参数仍在 ESP32 适配器内。

保留 32 通道槽位，按 8 个 32 位通道验证：每帧 37 字节，目标有效上传 1156250 B/s（9.25 Mbps），应用带宽预算 2000000 B/s。该预算不是无线物理速率或实测吞吐上限。固定采样率下，32 个 32 位通道超预算会拒绝启动，不能由上位机降低采样率。

实板对照记录位于 FRAME：`build/scope-throughput-baseline/result.json`（10 kHz / 10 s）、`build/scope-throughput-25k/result.json`（25 kHz / 45 s）、`build/scope-throughput-40k-bounded/result.json`（40 kHz 约 9 s 后中断超时，无队列溢出）、`build/scope-throughput-31250/result.json`（31.25 kHz / 约 91.6 s，实际约 1155911 B/s，计数连续、无溢出或中断超时）。因此采用 31.25 kHz 作为验证固件档位，不宣称它是芯片绝对最高速率。

### 15.3 SECTION 接入与软硬件边界

通用服务使用 `REG_TASK(1, manage)` 管理配置、链表、请求及应答，只提供 `realtime_scope_service_sample()` 采样入口。`REG_INTERRUPT(255, sample_interrupt)` 放在 `code/business/demo/demo_realtime_scope.c`，实际产品自行决定注册位置及优先级。示波器不配置、启停硬件中断；若控制 ISR 已经调用 `section_interrupt()`，无需额外调用采样函数，也不能再重复分发。

```c
/* 在已有控制初始化中、示波器服务绑定之后，声明实际中断频率。 */
bool ready = realtime_scope_service_source_set(CONTROL_SAMPLE_HZ);

/* 这是已有控制 ISR 的分发位置，不新增示波器定时器。 */
void existing_control_isr(void)
{
    /* 已有外设应答、ADC/控制流程由原工程负责。 */
    section_interrupt();
}
```

采样源声明仅允许在停止采集时变更；默认 0 Hz 表示尚未接入，命令 6 返回状态 5。命令 7 中历史 `timing_fault` 字段保留为 0，该服务没有自己的定时器监测。临界区、地址范围及固件标识由 BSP 提供，初始化和控制处理均在主任务中完成；临界区仅保护共享状态及单帧出队，网络 I/O 在临界区外。

Wi-Fi 模块统一管理 TCP 5000/9001 的生命周期，数据连接通过回调取完整 EA 帧后聚合发送；每轮最多 16 个 8192 字节块，EAGAIN/部分发送保留尾部，断开即丢弃旧尾部。项目源码不使用 FreeRTOS API、任务或队列；ESP-IDF 自身的 Wi-Fi 和系统运行时依赖保留在 SDK。

先前的 ESP32 SECTION 重构版本没有接入板级采样中断，实际返回 0 Hz。该历史版本的公共通信检查记录位于 `platform/esp32c5/build/section-scope-flash-smoke/result.json`，ELF SHA256 为 `26b7dde4e0fe43c320e0e17e72da0fa1f3d105c53952d0534e8f4909c8e8aa6c`，不能作为后续固件的采样证据。

当前 ESP32 demo 在 `bsp/bsp_timer.c` 提供独立于示波器的通用板级 GPTimer：1 MHz 计数、32 tick 自动重装，配置频率为 31250 Hz。Interface 的 `platform_bindings.c` 通过 `REG_INIT(1, control_interrupt_init)` 将硬件回调绑定到 `section_interrupt()`；`realtime_scope_bindings.c` 在优先级 2 初始化后将定时器实际配置频率传给示波器服务。demo 在优先级 254 查只读波形表并更新 RAM，优先级 255 注册的采样函数随即读取通道。实际产品已有控制 ISR 时使用该 ISR，避免重复分发。没有新增 FreeRTOS 任务或 API。

### 15.4 采样连续性及停止原因诊断

ESP32-C5 验证工程使用 `CONFIG_COMPILER_OPTIMIZATION_PERF`，保留 ELF/DWARF。HR8 板上的采样队列通过 Interface 放入 4 MiB PSRAM，8 个 32 位通道约可容纳 3.6 s 数据，内部 RAM 留给 Wi-Fi；无外部 BSS 配置的构建回退到 64 KiB。通用核心只接收队列指针和容量，不识别 MCU 或 PSRAM。

设备状态应答记录当前队列、高水位、出队帧数及溢出次数。BSP 的 `g_bsp_timer_debug` 记录 CPU 时间戳、间隔和中断执行开销；`g_bsp_wifi_debug` 记录任务轮询间隔、发送耗时、接受字节数和背压次数。它们不改变 EA 帧格式，也不在中断中打印日志。历史 `timing_fault` 仍固定为 0，不能把它当作硬件计时验收。

上位机 TCP 预留 1 MiB 接收缓冲，每次最多读 64 KiB；操作结果在通信锁外序列化一次并缓存，释放大批 JSON 数据也在锁外进行。`realtime_scope_device` 和 `realtime_scope_rx` 日志分别记录设备状态与接收缺口、重复及校验错误，区分采样缓存溢出、接收队列溢出和连接故障。

默认打开通道页，X/Y 测量游标不勾选，触发 T 保持显示。停止波形跨 500 ms 模式边界缩放时保留完整原始快照，按当前可见区重新抽取显示点并保留两侧相邻样本，避免极限放大时波形消失；触发、测量及原始点值不被插值改写。

### 15.6 时基与历史缓存分离

历史环形缓存按设备 Hz 和所设历史容量分配，时基仅改变显示窗口。修改窗口或跨越 500 ms 的滚动/触发模式边界，不重建缓存、不重置采样编号、不清空已接收点位，也不向下位机重发采集配置。运行时仅超过历史容量的旧点自然过期。

冻结或停止时保存当时所有尚在历史容量内的原始点位，而非仅保存屏幕窗口。冻结后后台继续接收至实时环形缓存，冻结快照独立保留；改变时基不解除冻结。缩放和平移只从保留数据中选择绘图点，游标读原始点值，测量按当前可见区计算；自动设置使用当前保留数据。继续/重新触发后恢复实时显示，新采集、通道布局或数据源切换才建立新的缓存段。

正常刷新仍只复制当前显示区，冻结/停止至多额外保留一份完整容量快照；后续缩放复用快照数组，避免每次时基变化重新分配全历史数据。实时缓存的 16000000 个 double 总点数预算保持不变，冻结快照按同一容量有界。

2026-10-22 GD32E507 实际 WPF 页面通过 8 通道、10000 Hz、60.210 s/601566 组数据测试，运行期间更改时基 30 次，含 0.01 ms、500 ms、10000 ms 及模式切换。停止后每通道完整保留 100000 点；冻结的 41453 点在后台环形缓存完全覆盖后仍逐点一致，并可继续缩放。计数跳变、EA 缺口、重复、校验错误、设备溢出均为 0，数据链路 TX 为 0。FRAME 记录和截图：`build/scope-gd32-history/`。独立 UI 回归还验证了停止/冻结跨边界、极限缩放及恢复采集；这项接入没有修改示波器下位机核心或 demo。

### 15.7 Demo 波形参数

共享 `demo_realtime_scope.c` 通过 `REG_SHELL_VAR` 注册 `DEMO_SCOPE_AMPLITUDE`（FP32，0～20，默认 2）和 `DEMO_SCOPE_FREQUENCY`（UINT32，1～500 Hz，默认 50），从上位机“参数读写”列表经公共 E8 链路设置。前者为正弦峰值，余弦与三角波峰值为其一半，方波保持 0/1；后者改变四种波形频率。复位恢复默认，不写入 Flash。

任务中的参数回调校验范围并发布对齐的 32 位增益位模式和频率；中断分别读取一次，按固定采样源 Hz 推进相位。默认幅值直接查表，非默认幅值仅对三个模拟量各乘一次增益，不计算三角函数。两个参数独立生效，不保证同时原子切换；不重置相位、不改变采样率、不触碰通道链表和采样缓存。低采样率接入时拒绝生成超过奈奎斯特频率的波形。

### 15.8 GD32 TCP 发送背压与任务让出

底层 `Basic/ethernetif.c` 原来在 DMA 描述符被占用时循环等待。现改为单次检查并返回 `ERR_MEM`，不复制数据、不修改忙描述符；超过 DMA 缓冲长度返回 `ERR_BUF`。网卡 DMA、硬件网络校验和以及现有有界数据复制保留。

LwIP 2.2.1 在链路输出失败时保留 TCP unsent 段。公共 TCP 5000 的发送任务每轮主动调用 `tcp_output`，即使应用数据已全部提交且没有新数据或 ACK，也会重试；暂时忙不计为链路故障。上传端点的 `bsp_tcp_stream_poll` 原本就每轮重试，继续共用该底层行为。所有 raw API 仍在单一网络任务上下文执行，未确认数据继续保留到 ACK，不在中断中等待或发送。

`g_enet_task_poll_count` 记录完成的网络任务轮数，`g_enet_tcp_tx_busy_count` 记录公共 TCP 输出暂时忙的次数，便于区分任务等待与网络背压。没有修改示波器核心、服务、EA 协议、采样频率或缓存容量；这次是通用网卡发送路径修复。

主机回归直接编译生产 Ethernet port 和 LwIP，验证连续 10000 次 DMA 忙返回不覆写缓冲、长度检查、链式 pbuf 复制，以及实际 TCP unsent 保留与无新数据重试。运行 `platform/gd32e507/tests/enet_nonblocking/test.ps1`；超时会终止测试，避免旧版等待循环挂住测试进程。原 TCP BSP 的回绕、延迟 ACK、ERR_MEM、会话隔离和错误路径回归也通过。

实板注入在停止采集时进行：J-Link 不暂停 CPU，清除发送 DMA 使能 750 ms，通过 UDP 回显填满描述符，并在同一公共 TCP 会话查询能力。最终固件期间网络任务完成 994 轮、TCP 忙返回 580 次，等待的应答在约 0.781 s 后正常返回，恢复 DMA 后再次查询通过，固件 SHA256 与 ELF 一致。该验证针对任务可继续运行及 TCP 恢复，不代表 750 ms 停顿期间实时采集不溢出。记录：`platform/gd32e507/build_realtime/hardware-nonblocking.json`、`dma-pressure.log`、`dma-restored.log`；复验脚本为 `tests/test_tcp_nonblocking_hardware.py --frame-root <FRAME目录>`，必须独占设备且停止采集。

### 15.9 双 2500 B 缓存与 1 ms 批次试验

按用户要求，将 Interface 的采样缓存从 16384 B 改为 2500 B，将独立 TCP 9001 的应答保留环从 8192 B 改为 2500 B。1024 B 取包暂存保留，三块数组共 6024 B；公共 TCP 5000 的缓存不变。BSP 利用 LwIP 单调毫秒时钟，每经过至少 1 ms 聚合一次新数据，每轮最多四批；不补跑遗漏的周期。连接管理、断线处理和已提交 TCP 数据的输出重试不受此门控限制，仍在单一网络所有者任务中运行。

批次间隔是后台任务的调度目标，不是硬件定时发送保证。主机测试验证同一毫秒内不重复取包、毫秒计数回绕、2500 B 环形回绕、延迟 ACK、ERR_MEM 和会话隔离。为实板诊断增加 `g_bsp_tcp_stream_debug`，记录整个连接期间的批次数、最大批次间隔、发送环高水位及背压次数；不改示波器核心或 EA 协议。

2026-10-22 当前试验固件已经编译、烧录并回读校验 154652 B，ELF SHA256 为 `7BEC610CA01E6C2955A0D6A78ED7238D64705FE5C4BC7EEEF9B27A6FB8714094`。RAM 为 105872 B/128 KiB（80.77%），相较 16 KiB/8 KiB 基线减少 19552 B。按模块输入段统计，示波器、专用上传链路和 demo 合计约 8124 B，另有共用网络栈、DMA 及任务栈。

实板测试未通过：8 个 32 位通道、10000 Hz，37 B/帧，采样队列最多 67 帧，约 6.7 ms。实际 GUI 测试收到 92 组后发现溢出，原生链路对照也复现；诊断版本原生测试约 32 ms 内返回设备溢出。连接统计的最大批次间隔为 11 ms，TCP 环高水位为 2479 B，未记录 tcp_write 或 tcp_output 的 ERR_MEM。统计包含采集前后时间，尚不能将调度和 ACK 等待分别定量归因。它证明本次配置不能保证 8 通道/10 kHz 连续采集，不能用先前大缓存版本的通过记录替代。数据停止后不静默丢弃继续运行，保持原有溢出停采机制。

结果路径见 demo 文档的小缓存段。该轮双小缓存试验记录保留；后续按用户要求恢复 TCP 设置的对照见 15.10。

### 15.10 保留 2500 B 采样缓存、恢复 TCP 的对照

### 15.11 SRTOS 运行确认与双小缓存复验

### 15.12 小缓存溢出根因：PendSV 切换期间重复请求

8 个 32 位通道的 EA 帧长为 37 B，10000 Hz 时产生 370000 B/s，即每毫秒 370 B。2500 B 采样队列可存 67 帧（2479 B），承受约 6.7 ms 的取包停顿。TCP 的 2500 B 环按 ACK 释放，不能仅按每轮新增字节估算占用；网络任务不能执行时，也不能把两块缓存直接视为一块 5000 B 的采样空间。容量设计依据是产生速率乘以最大释放延迟，再留余量；1 ms 是发送调度目标，并非延迟上限。

临时调度追踪在第一次采样溢出时冻结。实板记录显示：100 μs SysTick 抢占正在执行的 PendSV，此时旧任务的时间片尚未重置，`section_task_irq_exit_request` 再次挂起 PendSV。首次切换选中网络任务后，处理器立即尾链进入第二次切换，把尚未获得时间片的网络任务挂到未完成队列；其他短任务持续执行，网络服务延迟恢复，采样队列填满。一次记录的 tick 172540 同时出现“PendSV 活动期间重复请求、网络任务选中、网络任务被抢占”，此前最后一次完整网络任务在 tick 172528；随后直到溢出都没有恢复网络任务。追踪证据为 `platform/gd32e507/build_realtime/root-trace3-read.log` 和 `root-trace3-decoded.json`。

修复位于共享 SRTOS M 的 IRQ 退出调度入口：上下文切换已经处于活动状态时不再发出新的切换请求。`platform.h` 提供 `SECTION_PORT_CONTEXT_SWITCH_ACTIVE()`，统一映射 Cortex-M 的 `PENDSVACT`，未提供该硬件能力的环境返回 0。保持原有注册 API、默认 1 ms 时间片、两个忙等压力演示任务、10 kHz 采样、双 2500 B 缓存、1 ms 聚合及网络任务分工不变；临时追踪已移除，示波器核心与服务没有保留诊断修改或平台分支。

主机回归 `tests/host/section_irq/test_irq_exit.ps1` 编译生产 IRQ 退出、调度启动判断和时间片判断函数，仅替换 SCB、时钟与 PendSV 请求端点，覆盖活动 PendSV 不重挂、新任务完整时间片、到期切换、其他异常活动位及计时回绕。TCP 环形缓存、1 ms 门控和延迟 ACK 回归也通过。

实板原生链路连续 120.000 s，通过 8 通道、10000 Hz、1199877 组接收数据测试；EA 缺口、重复、校验错误、采样计数跳变和设备溢出均为 0，50 Hz 波形每周期恒为 200 点。采样队列峰值 20 帧（740 B），TCP 环峰值 1221 B，连接期间最大聚合间隔 2 ms，发送空间不足、`tcp_write` 暂忙和 `tcp_output` 暂忙均为 0。记录在 FRAME `build/scope-gd32-pendsv-long/`，设备 `build_realtime/pendsv-long-stats.log`。

### 15.13 按用户定义切换为固定全局窗口

15.12 修复了重复 PendSV，但当时仍是选中任务后重置时间片。用户随后明确要求固定全局窗口：窗口到期挂起当前任务并放入队尾，新到期任务优先，没有新任务再按 FIFO 恢复挂起任务，任务完成或恢复都不重置窗口。当前 SRTOS M/A9 已按该语义调整，移除 Ready 连选上限；M 系列保留短任务内联调度，并对完成、扫描和选择过程采用短临界区，避免窗口中断打断队列事务。

挂起期间保留任务的 `time_last`，完成后才重新判断下一轮资格。裸机、M 和 A9 共用相同的周期推进规则：不足两个周期时加一个周期，达到两个周期时更新到本次检查 tick。算法及配置详见 [SRTOS 设计](../framework/srtos/srtos.md) 和 `tests/host/section_irq/test_schedule.ps1`；测试直接编译生产策略函数，覆盖 Ready 优先、挂起 FIFO 和重新排尾、600 μs 执行后的窗口余量、忙任务保留到期资格、长延迟重同步和 tick 回绕。
