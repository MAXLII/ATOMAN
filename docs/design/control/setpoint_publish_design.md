# 控制参数发布与实时快照设计

控制参数同时存在于两个时间域：应用任务可以连续修改目标值，控制ISR必须在一次控制计算中看到一组前后一致的参数。active/building模型把“编辑参数”和“消费参数”分开，通过显式发布点建立两个时间域之间的所有权边界。

## 1. 设计目标

- 应用侧能够分多次构造一组完整设定值。
- 控制侧只读取稳定的active快照。
- 参数改变在明确边界生效，而不是某个字段写完就部分生效。
- 未发生发布时，控制ISR不重复复制整组参数。
- 浮点物理量和整数代码域使用相同的生命周期模型。
- 运行模式、方向等危险参数可以附加状态锁定策略。

## 2. 双缓冲模型

```mermaid
flowchart LR
    A["应用、通信、参数管理"] -->|"set_*"| B["building\n编辑中的候选配置"]
    B -->|"publish / version++"| P["发布边界"]
    P -->|"sync"| C["active\n控制侧稳定快照"]
    C --> I["控制ISR"]
```

building由应用侧拥有。多个setter可以依次修改功率限值、电压参考、电流限值和运行许可，期间active保持不变。publish表示候选配置已经完整，控制侧随后把它复制到active。

active由控制侧消费。控制算法不直接引用通信payload、Shell变量或参数存储区，避免外部数据生命周期和实时计算耦合。

## 3. 版本号的含义

active和building各自带有version：

```text
active.version == building.version  → 没有待消费发布
active.version != building.version  → building包含一版新快照
```

version是发布代次，不是单个字段的修改次数，也不是持久化配置版本。控制侧完成结构体复制后，把active.version更新为building.version，表示这一版已经被消费。

版本号回绕不会破坏“不相等即需要同步”的判断；但它不能统计错过了多少版，也不能证明中间版本都被控制侧使用。该模型有意采用“只消费最新配置”的邮箱语义。

## 4. 两种当前发布路径

仓库中存在两种实现形态：

### 4.1 延迟到控制侧同步

Buck、Boost、LLC和CLLC等模块的publish主要递增building.version，控制入口调用`*_cfg_sync_building_to_active()`或fast版本完成复制。

优点是active只在控制侧选定的边界变化，时间归属清晰。代价是一次结构体复制进入控制执行预算。

### 4.2 发布时立即复制

PFC等模块的`*_cfg_publish_building()`会递增版本并立即把building复制到active，控制侧sync只处理发布后的后续变化。

优点是控制入口减少一次等待；代价是应用任务可能直接写active，必须保证发布不会与ISR读取同一结构体并发。

两种路径应保持同一个外部语义：调用publish之前，修改不对控制侧生效；publish之后，下一次允许的控制边界使用完整新快照。

## 5. 一致性不由结构体赋值自动保证

C语言的整个结构体赋值通常被编译成多次字或字节访问，不具备天然原子性。version也不是完整seqlock：应用写building期间没有先把版本标记为“正在写”，控制侧无法仅靠一次版本比较发现写入正在进行。

当前模型成立依赖以下并发契约：

- building只有一个逻辑写者；
- setter和publish在同一串行执行域内调用；
- publish完成后，应用在控制侧sync完成前不继续修改building；
- 立即复制型publish不能与控制ISR并发读取active；
- 更换building指针时，旧、新缓冲区都具有足够生命周期。

如果平台无法满足这些约束，需要在publish/sync边界增加短临界区、三缓冲、双版本seqlock或原子指针交换，不能只增加`volatile`。

## 6. 发布时机

合理发布点通常是：

- 一条完整通信命令的所有字段已校验并写入building；
- 参数文件全部读取并完成单位转换；
- FSM允许新的运行配置生效；
- 控制环进入本周期计算之前。

不应在每个setter内部自动publish。多个相关字段如果逐个发布，控制侧可能使用“新电压参考 + 旧功率限值”的组合。

## 7. 物理量与代码域

浮点控制模块通常在building中保存物理SI量。Buck、Boost等整数控制模块的setter接收物理量后，先根据ADC/PWM比例转换成代码域，再写入building。

转换应发生在非实时编辑侧：

```text
物理配置 → 范围检查 → 比例换算 → building代码值 → publish
```

active进入ISR后应已经满足数值域和限幅要求，避免快速路径重复做单位换算和配置合法性判断。

## 8. 危险参数的状态锁

并非所有参数都能在run状态动态修改。CLLC方向会改变功率流、桥臂动作和控制器集合，因此使用独立方向锁：

- idle 状态解锁并接受方向更新；
- 离开 idle 前锁定；
- startup、run和fault期间拒绝方向变化；
- 停止回 idle 后才能发布另一个方向。

状态锁和双缓冲解决不同问题：双缓冲保证一组数据一致，状态锁保证某类变化只在安全运行阶段发生。

## 9. 控制侧同步边界

同步应放在使用新参数不会破坏当前计算的位置，例如ISR入口或慢速控制任务开始处：

```text
sync active
  → 读取反馈
  → 计算控制器
  → 更新PWM
```

不能在一次控制计算的中间同步，否则前半部分与后半部分会使用不同参数代次。大型快照需要测量复制时间，把最坏耗时计入ISR预算。

## 10. 失败与诊断

- active或building指针为空：配置未完成，禁止进入run。
- setter输入越界：拒绝或限幅后再写building，不能把非法值发布给ISR。
- 发布频率高于控制消费频率：允许合并为最新值，但应提供丢版统计时才可声称每版都生效。
- version长期不一致：说明控制侧没有执行同步或同步入口失效。
- 运行状态收到被锁参数：保持原active并记录拒绝原因。

## 11. 设计权衡

active/building以一份额外结构体和一次发布复制换取控制侧快照稳定。它适合“小规模配置、最新值优先、单写者”的控制系统。

它不等同于通用多生产者消息队列，也不自动解决跨核Cache一致性。参数量很大、写者很多或每一版都必须处理时，应使用邮箱队列、原子指针交换或显式进程间通信。
