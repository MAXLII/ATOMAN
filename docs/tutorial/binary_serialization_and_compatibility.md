# 二进制序列化与兼容基础

## 1. 内存对象不等于线格式

C 结构体是编译器用于访问内存对象的布局，通信报文是跨时间、跨程序和跨平台保存的字节契约。两者可能看起来相同，但结构体布局会受到以下因素影响：

- 成员对齐与填充；
- 编译器和 ABI；
- 整数、枚举和 `bool` 宽度；
- CPU 字节序；
- 位域分配规则；
- 浮点表示；
- 未对齐访问能力。

因此，不能默认把结构体地址强制转换为字节指针后发送，就获得了可移植协议。

## 2. 字节序

多字节整数需要规定高低字节顺序。以 32 位无符号整数的小端编码为例：

```c
static void write_u32_le(uint8_t *p_data, uint32_t value)
{
    p_data[0] = (uint8_t)(value >> 0U);
    p_data[1] = (uint8_t)(value >> 8U);
    p_data[2] = (uint8_t)(value >> 16U);
    p_data[3] = (uint8_t)(value >> 24U);
}
```

接收端用相反过程组合整数。显式移位比依赖主机字节序更容易审查和测试。

## 3. 对齐与未对齐访问

报文中的字段不一定满足处理器自然对齐。把 `&buffer[1]` 转成 `uint32_t *` 并解引用，可能产生异常或未定义行为。安全方法是逐字节组合，或复制到正确对齐的本地对象后再解释。

`packed` 可以减少结构体填充，但不能保证处理器安全访问打包后的未对齐成员，也不能自动解决字节序问题。

## 4. 位域与联合体

C 位域的位序、存储单元和跨边界规则由实现决定。联合体类型重解释也受到语言规则、字节序和编译器扩展影响。

稳定协议应把标志保存为固定宽度整数，并使用掩码：

```c
#define STATUS_READY_MASK (1UL << 0U)
#define STATUS_ERROR_MASK (1UL << 1U)
```

这样每一位的线格式含义都由协议定义，而不是由编译器决定。

## 5. 固定布局结构体

在编译器、ABI 和处理器均受控的封闭系统中，可以使用打包结构体提高开发效率，但应至少满足：

- 只使用固定宽度整数；
- 显式规定字节序；
- 禁止指针和平台相关枚举；
- 对 `sizeof` 和关键 `offsetof` 做静态断言；
- 用实际目标编译器执行报文字节测试。

固定布局结构体是一种受约束的实现选择，不是天然可移植的序列化格式。

## 6. 长度驱动的版本兼容

一种简单兼容方法是保持已发布字段不变，只在尾部追加新字段。接收端把本地对象清零，再复制：

```text
copy_length = min(received_length, local_object_size)
```

这样：

- 旧接收端面对新报文，只读取自己认识的前缀；
- 新接收端面对旧报文，新增尾部字段保持默认值。

但接收端还必须定义完成当前操作所需的最小前缀长度。长度小于最小值时应拒绝，而不是把缺失的必需字段也当作默认值。

## 7. 为什么不依赖保留字段

预留若干零字节看似能支持未来变化，实际会固定无意义布局，并不能预知未来字段的类型、对齐和语义。尾部追加配合长度字段通常更直接，也更容易让旧端忽略未知内容。

## 8. 固定前缀、TLV 与版本号

| 形式 | 特点 | 适合场景 |
|---|---|---|
| 固定前缀加尾部追加 | 解析简单、开销小 | 字段稳定的小型嵌入式协议 |
| TLV | 未知字段可跳过、扩展灵活 | 可选字段多、生命周期长的协议 |
| 显式版本分支 | 可表达破坏性变化 | 无法保持旧字段语义时 |

版本号不能替代长度和边界检查。即使版本合法，报文也可能被截断、损坏或恶意构造。

## 9. 请求、应答与事件

直接应答表示接收端对同一请求的处理结果，应能关联原请求。由请求触发的后续完成通知属于事件，不应冒充直接应答。

耗时操作通常分为：接受请求、后台执行、上报完成。协议应分别定义“已接受”和“已完成”，避免发送方把 ACK 当成最终结果。

## 10. 完整性与安全性

CRC 能发现随机传输错误，但不能证明发送者身份，也不能抵抗主动篡改。需要安全边界时，应使用消息认证码或数字签名，并包含会话、序号、长度和关键头字段，防止重放与字段替换。

## 11. 测试方法

协议测试应直接比较字节序列，而不只比较解析后的结构体：

- 已知字段值对应的黄金字节；
- 最小长度、完整长度和额外尾部字段；
- 每个字节位置的截断；
- 最大值、零值和非法枚举；
- 错误字节序和未对齐起始地址；
- 重复、乱序和迟到报文；
- 不同编译器或不同优化级别的交叉验证。
