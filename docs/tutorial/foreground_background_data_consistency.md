# 前后台数据一致性基础

## 1. 问题从哪里产生

嵌入式程序经常由不同执行上下文共同访问数据：中断读取控制参数，后台任务更新参数；DMA 写入缓冲区，CPU 读取结果；一个核发布状态，另一个核消费状态。

数据竞争不只意味着“两个线程同时写”。只要一个上下文写、另一个上下文在没有同步关系时读，就可能得到旧值、半更新值或彼此不匹配的一组字段。

## 2. 原子性、可见性与一致性

这三个概念不能混为一谈：

- 原子性：一次访问不会被观察为多个中间步骤。
- 可见性：一个执行者的写入何时能被另一个执行者看到。
- 一致性：消费者看到的多个字段是否属于同一次完整发布。

单个自然字长的读写可能是原子的，但一整个结构体赋值通常不是原子操作。即使每个字段都能原子读写，消费者仍可能同时读到新版本的字段 A 和旧版本的字段 B。

## 3. `volatile` 能做什么

`volatile` 告诉编译器每次都按语言规则执行该对象的访问，常用于硬件寄存器或会被异步改变的简单标志。它不提供：

- 多字段事务；
- 读改写原子性；
- 执行上下文之间的互斥；
- 多核缓存一致性；
- 完整的内存顺序保证。

因此，把共享结构体声明为 `volatile` 并不能解决参数快照的一致性问题。

## 4. 临界区

最直接的方法是在复制期间禁止可能并发访问的执行上下文：

```c
enter_critical();
shared_value = new_value;
leave_critical();
```

临界区适合短小、固定时间的更新。其代价是增加中断延迟或任务阻塞时间。大结构体复制、外设等待和不确定循环不应放在关中断临界区内。

## 5. 双缓冲发布

双缓冲把“构建”和“使用”分离：生产者只修改 building，完成后发布；消费者在安全边界把新版本同步到 active，然后在整个处理周期只读 active。

```text
生产者：修改 building → 发布版本
消费者：检测新版本 → 同步 active → 使用 active
```

这种方法使相关字段能够成组生效，也把切换点固定在消费者可控的位置。它仍需要并发契约：复制过程中生产者不能再次修改同一份 building，或者必须用临界区、序列锁、指针交换等机制保护。

## 6. 版本计数器

版本号可以表示“有新数据”，但普通的版本号前后检查并不自动构成同步原语。

简单版本模型适合单生产者、单消费者且双方切换时机受控的系统。版本号应使用无符号整数，并用“不相等”判断更新，允许自然回绕；不要假设版本号永远单调增大且不会溢出。

## 7. 序列锁

序列锁适合读多写少的数据快照。写者开始时把序号改为奇数，完成后改为偶数；读者复制前后读取序号，只有两次相等且为偶数时才接受快照。

```text
写者：seq++ → 写数据 → seq++
读者：读 seq1 → 复制 → 读 seq2 → 校验
```

序列锁允许读者重试，不适合读者不能重试的严格固定时长路径。实际实现还必须使用平台提供的原子操作和正确内存顺序。

## 8. 原子指针交换

生产者在未被消费者使用的缓冲区中构建数据，完成后原子交换“当前缓冲区指针”。消费者只读取已经发布的不可变缓冲区。

这种方法切换时间短，但需要明确缓冲区何时可以被重新使用。双缓冲在生产者可能追上消费者时并不总够用，必要时使用三缓冲、引用计数或消息队列。

## 9. 邮箱和消息队列

当每次更新都不能丢失，或者生产者和消费者速率差异较大时，应使用邮箱或队列。队列把所有权转移和排队规则显式化，但会增加存储、复制和调度开销。

“只关心最新值”适合快照；“每个事件都必须处理”适合队列。先判断数据语义，再选择机制。

## 10. DMA、多核与缓存

DMA 和多核场景还涉及缓存维护与内存屏障。CPU 写完描述符后，可能需要清理缓存并执行发布屏障；CPU 读取 DMA 结果前，可能需要失效缓存。屏障只约束访问顺序，不代替所有权协议和边界检查。

## 11. 选择方法

| 场景 | 常用方法 |
|---|---|
| 单个短标志 | 平台原子访问或短临界区 |
| 一组最新配置 | 双缓冲加明确发布边界 |
| 高频读、低频写快照 | 序列锁 |
| 不可变对象切换 | 原子指针交换 |
| 每个事件都不能丢 | 邮箱或队列 |
| DMA/多核共享缓冲 | 所有权协议、缓存维护和屏障 |

选择时同时评估最坏延迟、读写频率、是否允许重试、是否允许丢弃中间版本、内存占用和硬件内存模型。

## 12. 自检问题

1. 共享对象有几个写者、几个读者？
2. 消费者需要最新值还是每一次更新？
3. 一次更新包含几个必须一致的字段？
4. 复制能否被中断，读者能否重试？
5. 缓冲区何时归还给生产者？
6. 是否存在 DMA、缓存或多核访问？
