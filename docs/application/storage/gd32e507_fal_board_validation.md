# GD32E507 FAL 板上验证记录

## 验证范围

2026-09-05，对当前 `platform/gd32e507` 固件执行下载、启动检查、双 Flash ID 读取及 Demo test 分区擦写读回验证。固件为 `build/gd32e507_demo.hex`，包含 NAND 请求被拒绝时保留原缓冲区指针的修复。

本轮只触发 `DEMO_STORAGE_TEST`，未触发参数保存、日志追加或格式化。test 分区原有内容已被测试擦除覆盖，未做备份，不能通过本次记录恢复。

## 连接与下载

- J-Link 序列号：69409716；SWD 1000 kHz；目标电压约 3.24 V。
- 使用工程下载脚本，目标配置为 GD32E507ZE；探测到 Cortex-M33 r0p4。
- 内置 Flash 固件下载及校验通过，随后复位运行。
- 初始化计数 `s_demo_init_count=2`，两个 Flash 驱动初始化后错误码均为 0。
- J-Link 报告旧固件的缓存调试兼容性警告；探测结果显示本目标无缓存。

## 操作入口

COM4 为 J-Link CDC 串口，在 115200 baud 下进行 `FAL_INFO` 原始文本和参数列表查询均未获得有效响应，串口链路尚未通过验证。

本轮通过 ELF/DWARF 确认 RAM 命令邮箱地址，在初始空闲状态下由 J-Link 发布测试请求，使用现有存储服务、FAL Core、Interface 和 BSP 执行事务。通过数据池中的请求号、完成号、忙状态和结果码判断完成，并读取驱动诊断。

这条验证路径绕过 Shell 解析和业务请求提交 API，不构成对串口命令通道或命令提交 API 的板上验收。RAM 地址随构建变化，操作前必须重新从匹配的 ELF 确认。

## 实测结果

| 项目 | NOR | NAND |
|---|---|---|
| 实际 ID | `0x00C84015` | `0xC8F1801D` |
| test 分区 | `0x001FA000`，8 KiB | `0x07F40000`，256 KiB |
| 请求号 | 1 | 2 |
| 完成号 | 1 | 2 |
| 完成后 busy | 0 | 0 |
| 完成后 result | 0 | 0 |
| 完成后驱动 error | 0 | 0 |
| 完成后 corrected_bits | 0 | 0 |
| 完成后 bad_blocks | 0 | 0 |

每颗设备各执行 1 次测试事务，按顺序完成。现有 Demo 测试流程擦除 test 区的两个块，在第一个块末页写数据页、第二个块首页写提交页，并分别读回比较。结果为 0 表示该事务流程成功完成。

NAND 的读回经过现有 BSP 的 BCH/CRC 检查；纠错计数为 0 表示本轮没有报告已纠正位错误，不代表已验证纠错注入能力或全芯片无坏块。

## 验证边界

本轮已验证下载启动、设备识别、test 分区擦除、跨块编程和读回比较，覆盖数据池邮箱到存储服务、Core、Interface、BSP 的实际执行链路。

以下内容未在本轮实物验证：

- NAND 忙时重复请求被拒绝后原事务继续完成；该修复已有 40 项主机入口回归检查。
- 串口 Shell 与参数协议端到端操作。
- 参数分区保存、日志追加及重启恢复。
- 物理断电恢复、实际坏块和 ECC 位错误注入。
- 双设备同时请求、持续压力、延迟与任务周期测量。

本轮没有修改固件源码；目标已恢复运行。参数与日志分区未作为本轮擦写目标，但未对其执行前后全量内容比对。
