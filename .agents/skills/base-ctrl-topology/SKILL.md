# Base 控制拓扑固定格式

本技能的目的：下次增加一个拓扑时，生成与仓库控制模块一致的代码，既保持职责与接口格式，又容纳不同控制方法。统一的是所有权、生命周期和执行顺序，不是 PI 数值、物理模型或 PWM 参数。

仓库根目录以当前 Git 根为准，不依赖某台电脑的盘符。用户明确要求优先；既有模块的兼容性修改不自动授权全目录迁移。

## 先选路径

- **新拓扑**：先读 [固定格式与落地骨架](references/topology-contract.md)，按其中的数据表、函数表和步骤建立模块。再从 [各模块优点与差异](references/module-comparison.md) 选取最接近的控制机制，仅读对应源码。
- **已有模块修改**：先读目标模块的 cfg/hal/fsm/ctrl 和实际平台绑定，再对照固定格式。保持本次需求以外的 API、参数和用户编辑；不要为了统一而顺带改整个模块。
- **结构审查**：用固定格式检查所有权、注册顺序和动态数据通路；以模块对照表区分历史做法与推荐格式。不能把“文件齐全”当作合格。

适用的 C 语言要求遵循已安装的 `gnu-c-standards` 和仓库指令；本技能增加控制层职责，不复制整份 C 标准。

## 新拓扑必须固定的部分

1. 模块名使用小写拓扑名作为目录和公共符号前缀。核心是 `模块_cfg.c/.h`、`模块_hal.c/.h`、`模块_fsm.c/.h`、`模块_ctrl.c/.h`。每个文件都必须承担下面的实际职责。
2. **cfg**：持有应用运行请求、软起动配置及控制系数，形成待发布参数；不发波、不保存采样指针、不持有 PI 积分历史。应用的 `run_request` 与 FSM 授予的 `run_allowed` 分开。
3. **hal**：挂载模拟采样、确有需要的实时幅值/相位指针、发波和停波函数；另用 FSM HAL 挂载进入/退出运行及拓扑时序所需回调。不能把整个控制实例、配置池或平台对象挂进 HAL 来代替这些依赖。
4. **fsm**：唯一决定何时授予运行许可、何时提交参数；每个状态按 `in / exe / chk / out` 分工。INIT 检查绑定与初始化结果，通过后进入 IDLE；RUN 内不再判断绑定指针是否为空。
5. **ctrl**：一次采样形成快照；运行阶段读取完整参数快照，执行斜坡、算法、限幅和 PWM 回调。积分器、滤波器及调制历史只能由明确的执行上下文修改。
6. **应用保护**：过压、过流、欠压等判据和故障恢复策略放 `code/app/模块/`，使用本拍快照。ctrl 只提供抑制执行/停波机制；HAL 可提供硬件紧急停波执行能力，但不拥有应用阈值和保护策略。
7. 新控制链分别注册采样、应用保护、控制并发波，常用优先级为 `1 / 2 / 3`。算法计算和发波在同一个控制阶段。具体平台若已有其他优先级，先核对依赖，不能仅凭数字或文件先后猜顺序。

## 不随拓扑改变的约束

- 绑定对象必须覆盖整个运行期。INIT 成功后锁定绑定；重绑需要停止并重新走 INIT。实时相位、幅值是数据内容更新，不是更换绑定地址。
- 只在 INIT/绑定初始化入口检查依赖指针。有效运行路径不重复 NULL、`isfinite` 或通用参数检查，也不加入不可能到达的 INIT 分支。采样入口若在 INIT 期间仍会被调度，应由外层生命周期门控阻止解引用未绑定指针。
- **保留**运行请求/故障门控、调制限幅、积分抗饱和和定点溢出控制。这些是控制语义，不属于待删除的参数检查。
- 用户/通信输入的格式和范围由应用写入口或初始化边界负责；不能因为算法不重复检查就允许畸形输入直达计算。
- HAL 挂载的量由采样阶段每拍读一次。后续保护、算法、发波必须使用这份快照，不能发波时再读另一个时刻的母线电压。同步 DMA/ADC 快照由平台保证。
- 多字段参数发布必须完整且读取有界。优先复用 Buck/NPC 的单发布者快照设计；读失败沿用上次完整值，ISR 不能等待被自己抢占的任务。独立停机/保护信号具有更高优先级，不能因沿用旧快照而推迟停波。
- 序号或 `volatile` 本身不证明并发安全。采用原子字段或平台同步原语时，核对实际 MCU 的无锁性、内存序、抢占关系及对象寿命；禁止把主机线程模型的成立当成 MCU 证据。
- 生产控制使用 `float` 或已定义的定点域，不用 `double`；常量带 `f`，数学常量来自 `my_math.h`。定点模块必须写清 ADC 域、Q 格式、物理单位及 PWM 域；不强制改成浮点。
- 可复用纯算法放 `code/lib`，寄存器和载波细节放 interface/BSP。短计算可 `static inline`，中断热路径按平台用 `FUNC_RAM`。属性不等于整个调用链已在 RAM。
- 新增枚举类型采用 `模块_含义_E` 的全大写形式，指针成员用 `p_`，公共函数统一模块前缀；不复制旧代码中的小写枚举类型、双下划线保留标识符或无实际动作的兼容空函数。

## 从需求到代码

1. 先交代拓扑、采样与指令单位、输入/输出符号、控制/PWM 周期、实际更新延迟、调制方式、停机电平和启动条件。缺少的器件/硬件数据不能从其他模块猜测；只询问影响实现的缺项。
2. 用骨架中的表格列出结构体、每个字段的唯一来源与写入者、执行上下文、HAL 回调参数。实时幅值/相位若走 HAL，不再在 cfg 建第二个可写来源。
3. 写出状态和注册顺序，再建立八个核心文件；按需要补应用保护、interface、BSP 和构建源清单。新拓扑命名必须同时落实到文件、类型、函数和注册项。
4. 实现一个最小完整链：绑定 → INIT → IDLE → 请求启动 → 参数发布 → 采样 → 保护 → 控制并发波 → 停机。不能先写一堆空 API，再称为已经适配。
5. 只有拓扑确实需要时才加 SOFT_START、RELAY_WAIT、PRECHARGE、FAULT 或方向切换状态。结构统一不意味着所有拓扑都必须有这些状态。
6. 逐项检查下述验收，再报告改动和实际验证边界。不要擅自改模型、整定系数、保护策略或发布代码。

## 验收清单

- 文件职责、数据来源、函数顺序符合骨架；应用不能直接写运行许可或积分历史。
- INIT 未绑定不能到 IDLE/RUN；已进入有效运行后没有重复依赖检查。重复启动先复位状态，正常停机和故障抑制不会被后续控制重新发波。
- 采样、保护、控制顺序符合实际注册表；同优先级顺序按框架实现验证。平台不只打任务就绪标记，还实际执行任务/FSM 调度。
- 参数发布不撕裂、ISR 不自旋等待、系数批量更新无半新半旧状态。外环分频、慢任务更新时间必须明确。
- 软起动配置在 cfg，实际斜坡值在 ctrl；HAL 幅值/相位范围、单位、回调寿命以及 PWM 极性均写清。
- 数学模型和控制参数与新硬件匹配；没有照搬 NPC 的 5 kHz、2 µs、PI 数值或 690 V 目标。
- 修改代码时执行对应目标的严格构建与必要的生命周期/注册检查。仿真、主机测试和板上验证分别描述；只制作技能时不运行功率级仿真。

完成新拓扑后，交付真实代码、对应构建接入和验证结果。完成结构审查时，按“保留优点／偏离固定格式／本次是否修改”给出结论。
