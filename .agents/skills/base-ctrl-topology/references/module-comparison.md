# code/ctrl 模块优点与取舍依据

基于 2026-09-14 仓库中 11 个控制目录的静态阅读。这里的“优点”指结构上值得借鉴的职责和机制，不表示效率、稳定性或硬件安全已经证明最优。源码以后变化时，用下列文件/符号重新核对，不盲从这份快照。

文件链接相对本技能；从其他目录调用时仍按本文件的位置解析。

## 每个模块可借鉴什么

| 模块 | 最值得借鉴的结构 | 新拓扑如何使用 | 不应直接复制的部分 |
|---|---|---|---|
| [buck](../../../../code/ctrl/buck/buck_fsm.c) | 应用请求与 FSM 许可分离，`buck_fsm_publish_building/read_published` 提交完整控制参数；HAL 将多路电感电流与各路 PWM 成对组织 | 作为新模块配置所有权和参数快照的主要参考；多路控制显式写通道对应关系 | `init_exe` 中跨文件 `extern` 内部对象、旧小写枚举、硬编码硬件代码域；原子实现须核对目标 MCU |
| [boost](../../../../code/ctrl/boost/boost_ctrl.c) | `boost_task` 准备慢变电流预算，`isr_param_request_update` 将结果交给快环；独立控制/任务/PWM 周期及比较上限 | 复杂约束计算从快环分出，写清发布周期与 ISR 应用边界 | 不照抄旧通用就绪检查与任务直接重采样方式；不能把 Boost 的电流/占空比关系用于 Buck |
| [bb](../../../../code/ctrl/bb/bb_ctrl.c) | `bb_ctrl_cal_ol_mode` 将 Buck/Boost/过渡模式分配与环路计算分开；HAL 用一次回调提交两侧桥臂命令 | 多工作区拓扑将模式选择与执行分离，同一次调用提交相关输出 | ISR 反复判断一组 HAL 指针不符合新格式；浮点参数或功率区间不是别的拓扑通用值 |
| [llc](../../../../code/ctrl/llc/llc_fsm.c) | STARTUP 与 RUN 分离，startup 等待量来自配置；调制通过 HAL 输出而非直接碰寄存器 | 谐振拓扑保留真实启动阶段和输出语义，控制器只给调制命令 | 固定滤波、陷波及增益需按新对象设计；`llc_ctrl_set_p_hal` 空兼容接口和热路径 ready 检查不继承 |
| [cllc](../../../../code/ctrl/cllc/cllc_fsm.c) | 双向启动时锁定方向；STARTUP/RUN/FAULT 区分；[ctrl](../../../../code/ctrl/cllc/cllc_ctrl.c) 分离正向竞争控制与反向电压环，HAL 使用归一化调制命令 | 双向拓扑借鉴方向在生命周期边界切换、不同方向各自算法与统一调制入口 | 不把方向切换当可任意热写变量；旧路径中重复 NULL 检查不进入新模板；FAULT 的保护判据仍按新边界留在 app |
| [inv](../../../../code/ctrl/inv/inv_ctrl.c) | 相位计算单独注册在控制之前；幅值与频率分别斜坡；[FSM](../../../../code/ctrl/inv/inv_fsm.c) 管理输出继电器等待 | 需要自主角度发生器或实际继电器的逆变器采用这些机制 | 并非每个拓扑都内置角度/继电器；外部相位已给定时不再自建第二个发生器；共振环整定另算 |
| [inv_dq](../../../../code/ctrl/inv_dq/inv_ctrl.c) | 延时正交量、DQ 环路、解耦和反变换形成可追踪的数据链 | 保留坐标、相位和解耦量的明确来源，按信号链组织算法辅助函数 | 单相四分之一周期缓冲不是三相 Clarke；随频率变化的延时不能无条件当作理想正交量；空 HAL setter 不继承 |
| [inv_i32](../../../../code/ctrl/inv_i32/inv_ctrl.c) | 整数相位与三角函数；`prepare_frequency_coeff_task` 在慢任务准备系数，快环使用批量更新结果；HAL 注明代码域 | 作为无 FPU/有定点约束目标的计算域及快慢路径参考 | 普通 pending 标记的跨上下文语义需单独审查；不能因名字 `_i32` 就宣称整个调用链无浮点或跨线程安全 |
| [pfc](../../../../code/ctrl/pfc/pfc_fsm.c) | SOFT_START→MAIN_RLY→RUN 明确表达母线建立与继电器反馈顺序；[ctrl](../../../../code/ctrl/pfc/pfc_ctrl.c) 将观测频率更新请求和快环应用分开 | 需预充/继电器协同的拓扑沿用分阶段生命周期，硬件反馈挂 HAL | 不继承热路径重复就绪检查、ctrl 中的应用保护策略；单相电流参考形成方法不适用于所有 PFC |
| [pfc_i32](../../../../code/ctrl/pfc_i32/pfc_ctrl.c) | 整数电压/电流域与整数 SOGI/FLL；显式观测器快照和频率更新路径 | 需要定点观测与电流整形时借鉴单位及更新边界，保留 PFC 时序职责 | 物理值转代码的比例、溢出界限与实际硬件一并计算；读写快照协议不能因使用整数就免于并发审查 |
| [npc](../../../../code/ctrl/npc/npc_ctrl.c) | 采样优先级 1、[应用保护](../../../../code/app/npc/npc_protect.c) 优先级 2、控制发波优先级 3；外部幅值/相位、三相基波电流与母线快照一起进入调制；[FSM](../../../../code/ctrl/npc/npc_fsm.c) 有界读取完整参数 | 作为新模块中断三层、HAL 实时输入和同拍数据契约的主要参考 | 不照搬 5 kHz、2 µs、PI、DSOGI、正负序结构或中点算法；并非所有拓扑需要它们；其他旧 API 冗余也不因最新模块而自动成为标准 |

## 从比较中选出的共同标准

1. **外部依赖以 HAL 指针/动作表表达**：11 个模块都存在 cfg/hal/fsm/ctrl 分工，采样与 PWM 的 HAL 边界是最稳定的共同点。适配不同拓扑时改变字段与回调内容，不把平台对象或控制内部对象塞入 HAL。
2. **新拓扑以 Buck/NPC 的请求—许可分离为主线**：多个旧模块把 active/building、版本号和 setter 暴露得更广。保留这些模块的兼容行为，但新模板将发布者收敛到 FSM，应用只提出请求。
3. **保留 LLC/CLLC/PFC 的真实时序**：状态数不必一样，状态函数的职责应一样。控制与配置文件不是为凑八个文件而存在。
4. **新中断链采用 NPC 的采样—保护—控制发波分层**：旧 LLC/CLLC 将控制注册在优先级 2，旧逆变器还在优先级 0 计算相位，这说明历史数值并未全部统一。新模块先给出执行依赖再接入平台，不能全目录替换数字。
5. **慢计算与快应用分离**：Boost、inv_i32、PFC 的做法适合作为设计参考。发布协议须独立证明，不能把 `version++` 当作完成了多字段原子提交。

## 反例定位与限制

- [Buck FSM](../../../../code/ctrl/buck/buck_fsm.c) 的 INIT 直接 `extern buck_ctrl_hal`；新实现通过声明在头文件的 HAL 访问/就绪接口完成检查，不复制此访问方式。
- [CLLC cfg](../../../../code/ctrl/cllc/cllc_cfg.c) 的 `cllc_cfg_publish_building()` 只增加 building 版本号；这一函数单独不能证明整个多字段读写协议安全。应连同写入端、读取端和执行环境一起审查。
- [BB ctrl](../../../../code/ctrl/bb/bb_ctrl.c) 的 ISR 中成组 NULL 检查、[CLLC FSM](../../../../code/ctrl/cllc/cllc_fsm.c) 的启动/退出回调重复检查，不符合用户确定的“INIT 检查后运行期信任绑定”。技能采用新格式，不在制作技能时修改这些源文件。
- [LLC ctrl](../../../../code/ctrl/llc/llc_ctrl.c)、[inv_dq ctrl](../../../../code/ctrl/inv_dq/inv_ctrl.c) 的 `*_ctrl_set_p_hal()` 忽略参数，是兼容遗留，不能作为新接口的模板。
- 多个旧文件使用小写 `_e`、`__模块_H`。新增代码按全大写枚举 `_E`、非保留形式头文件保护宏书写；不因参考旧模块而放弃现行 C 规范。
- [Section 实现](../../../../code/section/baremetal/section.c) 显示小优先级先执行、同优先级稳定插入，`run_task()` 会推进并运行相应任务路径。仍需检查具体 MCU/PLECS 的调用点和链接注册顺序；注册存在不等于任务真正执行。

这次提炼没有改动已有控制源码、没有重新整定参数，也没有运行各拓扑的动态稳定性验证。用于新拓扑的固定函数与数据结构见 [topology-contract.md](topology-contract.md)。
