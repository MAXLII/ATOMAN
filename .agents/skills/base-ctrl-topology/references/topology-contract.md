# 新拓扑的固定结构与实现骨架

这里的 `topo` 表示新拓扑选定的唯一模块前缀；`TOPO` 表示其大写形式。创建时一次性替换成真实名称。骨架固定职责，不是可直接编译的通用变换器。

## 1. 开始编码前填清的接口表

| 项目 | 必须落定的内容 |
|---|---|
| 功率级 | 单/多相、桥臂数、单/双向、滤波器、参考中性点 |
| 模拟采样 | 字段、单位/代码域、极性、有效采样时刻和来源指针 |
| 外部实时输入 | 幅值、角度或同步信号是否由外部提供；角度是 rad、pu 还是定点相位 |
| 配置 | 周期、软起动斜率/时间、目标值、控制系数、调制限幅；哪些允许运行中改变 |
| 输出 | 控制电压、归一化调制量、频率/相移还是比较值；使能与停机行为 |
| 调用时序 | ADC 完成、采样快照、保护、运算、PWM 锁存的相对时刻；总延迟按实际平台填写 |
| 运行条件 | INIT 成功条件、启动时序、停止/故障条件、重新启动与方向切换的要求 |

不知道器件和延迟时，不用其他拓扑的数值补空缺。可先实现不依赖缺项的接口，但不得将未整定参数描述成稳定方案。

## 2. 文件与层次固定

```text
code/ctrl/topo/
    topo_cfg.h       配置类型、运行请求和配置访问接口
    topo_cfg.c       参数池、默认值、单位换算、构建快照
    topo_hal.h       控制依赖与状态机副作用回调的类型、绑定接口
    topo_hal.c       静态绑定对象、绑定锁、INIT 就绪检查
    topo_fsm.h       状态/事件定义、发布快照读取接口
    topo_fsm.c       生命周期、唯一参数发布者、REG_FSM
    topo_ctrl.h      必要的采样/输出类型和控制生命周期接口
    topo_ctrl.c      算法运行状态、采样与控制中断
code/app/topo/
    topo_protect.h   必要的应用保护接口
    topo_protect.c   本拍保护判据、故障锁存与恢复策略
```

按实际平台增加 `code/interface/topo/平台或common/` 与 `platform/目标工程/` 下的 app/BSP 绑定，不另造绕过现有 interface 的寄存器层。纯算法复用 `code/lib`。

有物理参数推导、定点缩放或大量器件参数时，增加 `topo_hw_param.h`；少量默认值不需要额外空文件。新模板默认由 FSM 私有函数发布快照，无需 `topo_cfg_fsm.h`。维护现有 cfg 持有发布缓冲区的模块时，保留其 `*_cfg_fsm.h` 作为 FSM 专用提交接口，不向应用公开提交权限。

## 3. 结构体固定角色

| 类型 | 放置 | 写入者/读取者 | 允许的成员 |
|---|---|---|---|
| `topo_ctrl_cfg_t` | cfg.h | INIT 建立，ctrl 使用 | 固定周期、已整定系数、算法限幅；没有积分历史 |
| `topo_cfg_t` | cfg.h，实例 cfg.c 私有 | 应用配置入口写，FSM 读 | 运行请求、软起动配置、应用目标；必要的请求同步字段 |
| `topo_ctrl_setpoint_t` | cfg.h | FSM 发布，ISR 读完整副本 | 算法使用的动态参数值和 `run_allowed`；不持有采样地址 |
| `topo_ctrl_hal_t` | hal.h | 平台在 INIT 挂载 | 模拟量指针、必要的实时幅值/角度指针、发波与停波回调 |
| `topo_fsm_hal_t` | hal.h | 平台/模块在 INIT 挂载 | 进入/退出运行回调，确有需求的接触器等生命周期能力 |
| `topo_ctrl_sample_t` | ctrl.h | 采样阶段写，保护与控制只读 | 本拍数值副本，包括发波所需母线、实时参考和相位 |
| `topo_ctrl_output_t` | ctrl.h | ctrl 写，应用/调试只读 | 实际给定、控制输出、状态和诊断；不得变成第二个指令入口 |
| `topo_ctrl_inter_t` | ctrl.c 私有 | 控制执行上下文唯一维护 | PI、滤波器、斜坡值、上一拍状态、待应用系数等 |
| `topo_fsm_published_t` | fsm.c 私有 | 单发布者写，ISR 有界读取 | 参数发布的同步表示；不是对外参数池 |

只有实际存在的角色才实例化。无需诊断输出时，不制造一组空 output/getter。多个算法实例确有需要时可用私有 `topo_ctrl_t` 聚合 cfg/inter/output；不要把这个实例通过 HAL 暴露给平台。

软起动参数（例如 V/s、Hz/s、等待时间）在 cfg，当前斜坡进度和实际参考在 ctrl。`run_request` 是应用意图，`run_allowed` 是生命周期许可，保护还有独立的执行禁止状态，三者不能混成一个可随意写入的变量。

如果幅值/相位是外部实时指令，HAL 挂载 `p_amplitude`、`p_theta`，采样时读入 sample；cfg 仅保存斜率等策略，不复制另一份同名可写幅值。NPC 的角度使用 rad、范围沿用 `0..M_2PI`；其他定点模块允许不同相位域，但必须显式标注并在边界换算。

## 4. HAL 的固定形状

示例只展示指针与回调形状，实际采样字段、通道数及 PWM 参数由拓扑决定：

```c
typedef void (*topo_pwm_setter_t)(float command);

typedef struct
{
    float *p_v_in;                      /* 输入电压，V；平台保证对象在整个运行期存在。 */
    float *p_v_out;                     /* 输出电压，V。 */
    float *p_i_l;                       /* 电感电流，A；正方向须按实际电路定义。 */
    topo_pwm_setter_t p_set_pwm_func;    /* 同步消费本拍控制命令。 */
    void (*p_pwm_disable)(void);        /* 禁止功率输出。 */
} topo_ctrl_hal_t;

typedef struct
{
    void (*p_enter_run_func)(void);     /* 在开始执行前准备控制状态。 */
    void (*p_exit_run_func)(void);      /* 退出执行，停止输出。 */
} topo_fsm_hal_t;
```

整数拓扑将采样和输出换成明确的整数代码域；多桥臂使用有意义的数组/结构化命令，不能复制这个单路示例。发波回调需要母线、使能、方向或三相电流时，明确参数及单位；若收到临时数组指针，必须同步消费，不留存地址。仅在真实下游会失败时定义状态返回值，并明确成功码。

HAL 只描述“依赖什么输入和动作”；ADC 平台驱动、DSP 内部状态、Shell 对象、整个数据池和 `.plecs` 对象都不属于 HAL 成员。

## 5. 函数固定职责与文件内顺序

所有 `.c`：文件说明 → 对应头文件及依赖 → 私有类型/常量/状态 → 内部计算辅助 → 生命周期/运行函数 → 紧邻函数的注册项 → 对外接口。函数必须展开花括号；注释说明单位、方向、所有权和时序，不逐行复述赋值。

| 文件 | 函数形状 | 固定职责 |
|---|---|---|
| cfg | `topo_cfg_init()` | 恢复参数默认值和停止请求；不调用未绑定硬件 |
| cfg | `topo_cfg_default()` | 返回控制系数配置；只在确实需要统一默认构造时提供 |
| cfg | `topo_cfg_set_参数()` | 接收已完成应用输入校验的请求，换算到约定域；不授予运行许可 |
| cfg | `topo_cfg_get_p_building()` | 返回待发布参数；其许可保持禁止，由 FSM 发布时覆盖 |
| cfg | `topo_cfg_get_run_request()` | 读取独立开停机请求；应用不能直接改 FSM 状态 |
| hal | `topo_hal_set_量_ptr()`、`topo_hal_set_动作()` | INIT 阶段挂载长期有效的指针和回调；锁定后不改变 |
| hal | `topo_hal_get_ctrl()`、`topo_hal_get_fsm()` | 返回模块私有绑定对象的受约束访问入口 |
| hal | `topo_hal_is_ready()` | INIT 检查所有必需依赖，不在算法中反复调用 |
| hal | `topo_hal_lock_binding()`、`topo_hal_unlock_binding()` | 维护绑定生命周期；只在停止后重入 INIT 才解锁重绑 |
| fsm | `topo_fsm_publish_building()` | 私有提交函数，形成完整参数加本状态许可 |
| fsm | `topo_fsm_read_published()` | 有界尝试读一致副本；失败不覆盖调用方旧快照 |
| ctrl | `topo_ctrl_init()` | 建立内部状态和初始禁止标记；不依赖未就绪采样 |
| ctrl | `topo_ctrl_prepare_run()` | 在禁止执行的边界复位算法、斜坡与历史，不重复检查 HAL |
| ctrl | `topo_ctrl_sample()` | 从 HAL 读取一次，形成这一拍的快照 |
| ctrl | `topo_ctrl_cal()` | 执行本拓扑计算、必要限幅；计算不直接读 HAL，不做通用参数/指针检查 |
| ctrl | `topo_ctrl_run()` | 门控 → 参数快照 → 控制计算 → 发波回调，包含发波动作 |
| ctrl | `topo_ctrl_stop()`、`topo_ctrl_inhibit()` | 正常停止/本拍故障禁止机制；不判定应用保护阈值 |
| ctrl | `topo_ctrl_get_sample()`、`topo_ctrl_get_output()` | 返回只读观察接口，按实际消费者提供 |
| app | `topo_protect_run()` | 在采样后判断本拍保护并请求抑制，控制前生效 |

没有实际消费者的接口不增加。特别禁止留下 `set_p_hal(p) { (void)p; }` 这样的空绑定函数；不要一边用 HAL getter、一边假装另一个 setter 也能改变绑定。

## 6. FSM 固定阶段

每个真实状态写四个函数，名字为 `topo_fsm_状态_in/exe/chk/out`。框架签名依现有 `REG_FSM`：`in/exe/out` 为 `void(void)`，`chk` 为 `uint32_t(uint32_t event)`；事件存储按框架用 `uint32_t`，枚举常量仍明确语义。

| 状态 | in | exe | chk | out |
|---|---|---|---|---|
| INIT | 撤销运行许可，允许挂载 | 等待绑定、配置、算法初始化成功；完成后锁定绑定 | 初始化事件转 IDLE | 不提前发波 |
| IDLE | 保持禁止执行/停波 | 处理合法启动请求、故障条件和待发布配置 | 转 RUN 或拓扑专属启动状态 | 为本次启动锁定方向等不可热切换信息 |
| RUN | 在算法未执行的边界完成 prepare_run，再授予许可 | 发布动态参数，响应停止/故障 | 转 IDLE 或真实故障状态 | 撤销许可并停止输出 |

`exe` 产生事件，`chk` 只决定转移，不混入发波或 PI 计算。框架要求空的无动作状态钩子可以保留并说明“本状态无退出动作”，不能为了凑文件创造整个无职责模块。

有预充、继电器反馈、谐振桥稳定等待等需求才增加相应状态。等待用调度 tick/截止时间，不在任务或 ISR 里忙等。双向拓扑把方向在启动边界锁定，运行中请求换向先停机；不是直接改变本拍调制方向。

不要在实际 RUN 回调中添加“如果不是 INIT 才停波”之类矛盾分支。`prepare_run`/`stop` 若由任务调用，必须证明此时 ISR 不再修改同一动态对象；无法证明时用单次请求在控制周期边界处理，并明确完成条件，不能只加一个普通标志假定同步成立。

## 7. 一拍执行骨架

```text
平台 ADC/同步源准备完成
    │
    ├─ REG_INTERRUPT(1, topo_ctrl_sample)
    │      INIT 门控通过后读取 HAL，发布本拍 sample
    │
    ├─ REG_INTERRUPT(2, topo_protect_run)   定义在 code/app/topo
    │      读 sample，判定保护，必要时禁止后续执行并停波
    │
    └─ REG_INTERRUPT(3, topo_ctrl_run)
           检查运行许可、独立停止请求和保护禁止状态
           尝试读取完整 setpoint；失败沿用上次完整值
           应用待生效的系数，更新软起动实际参考
           topo_ctrl_cal(sample, setpoint, inter, output)
           使用本拍 sample 和 output 调用 HAL 发波
```

小优先级先执行；同优先级次序取决于框架和注册顺序。相位预计算确有前置依赖时可以在更早阶段执行，不能未经平台审查就插入一个会改变其他模块顺序的注册项。控制输出需要“一拍后生效”时，把平台锁存行为写清；不要在 DLL 又增加一拍重复延迟。

外环分频时把分频计数、保持值与实际周期定义在 ctrl 中。慢任务只负责允许延迟的监测/系数准备，通过明确发布通道传给 ISR；不要在慢任务直接改正在运行的积分器。优先复用现有 Section 注册机制，不另建私有调度循环。

## 8. 拓扑适配顺序和审查场景

先定 HAL 和数据所有权，再做 INIT/IDLE 与绑定；接入一次完整采样及应用保护后，完成算法到真实 PWM 回调；最后补软起动、模式切换和调试数据。平台绑定应发生在允许绑定的初始化阶段，并进入实际构建清单。

对新实现至少检查这些行为，而非仅检查文件名：

1. 缺一个必需输入或停波回调时停留 INIT；补齐并初始化成功后进入 IDLE，RUN 不再做指针检查。
2. 软件请求启动不能绕过生命周期条件；本拍保护触发后，优先级 3 不会再发出使能命令。
3. 发布中被 ISR 抢占时立即返回旧完整快照，不读半新半旧数据、不等发布者恢复；停止请求仍及时生效。
4. 正常停止、启动中取消和再次启动的积分器/软起动行为明确，没有残留上一轮输出。
5. 换成另一个 BSP 时，ctrl 不改寄存器代码；发波单位和中断周期仍匹配。
6. 单精度和定点编译边界正确；跨平台原子操作、RAM 放置和注册顺序有目标侧依据。

若本次用户只要设计或技能，不生成业务 C 文件或运行仿真。若明确要求实现，完成上述真实链路，不能仅交付占位骨架。
